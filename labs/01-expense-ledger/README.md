# L01. Консольный журнал расходов

Реализуйте программу ExpenseLedger по этому контракту. Предварительно пройдите главы 01–09
и [разбор проекта](../../docs/01-foundations/10-project.md). Цель — связать язык и BCL в работающую утилиту.
Ориентир: 6–10 часов, включая самостоятельные проверки и исправления.

## Входные данные

Принимается ровно один аргумент: путь к файлу. Файл — UTF-8, необязательный UTF-8 BOM допустим.
UTF-16 и повреждённый UTF-8 отклоняются. Строки заканчиваются LF или CRLF; последняя может не иметь перевода строки.
Пустые строки и строки из пробелов пропускаются. Номер ошибочной строки считается по физическим строкам файла,
включая пропущенные. Заголовка и комментариев в формате нет.

Каждая непустая строка имеет ровно три поля:

```text
дата;категория;сумма
2026-01-10;food;12.50
```

Пробелы по краям каждого поля удаляются перед проверкой. Внутренние пробелы не удаляются.

| Поле | Правило |
| --- | --- |
| Дата | Ровно `yyyy-MM-dd`, настоящая календарная дата в диапазоне DateOnly |
| Категория | 1–32 ASCII-символа; первый — буква; остальные — буквы, цифры, `_`, `-` |
| Сумма | Только ASCII-цифры и необязательная точка; целая часть обязательна; после точки 1–2 цифры |
| Диапазон суммы | Больше 0 и не больше 999999.99 |
| Число записей | Не больше 100000 непустых корректных строк |

Разрешены `1`, `1.5`, `1.50`, `001.50`; запрещены `+1`, `-1`, `0`, `.5`, `1.`,
`1,50`, `1e2`, `1.234`, `NaN`, разделители тысяч.
Регистры категорий не различаются; в результате выводится нижний ASCII-регистр.
Повторные строки считаются отдельными расходами: правило дедупликации здесь не задано.

Лимит записей позволяет держать первый учебный вариант в памяти.
Это формат небольшой локальной выгрузки; потоковый импорт и лимиты байтов изучаются в следующих блоках.

## Результат

Сначала выведите count и total, затем категории в порядке StringComparer.Ordinal.
Суммы всегда имеют точку и два знака после неё. Культура компьютера не влияет на результат.
Успешный stderr пуст; порядок строк определён контрактом.

Для [valid.txt](data/valid.txt):

```text
count=3
total=50.00
food=20.00
travel=30.00
```

Для пустого файла:

```text
count=0
total=0.00
```

## Ошибки и коды завершения

| Код | Ситуация | Требование к stderr |
| --- | --- | --- |
| 0 | Успех | Пуст |
| 2 | Не один аргумент | Начинается с `usage:` |
| 3 | Ошибка пути, открытия или чтения | Начинается с `io:` |
| 4 | Ошибка данных или кодировки | `line N: причина` либо `encoding: причина` |

При любом ненулевом коде stdout пуст. Для ошибки данных достаточно сообщить первую;
номер строки обязателен. Текст причины после префикса может быть русским или английским.
При повреждении кодировки номер строки не требуется, поскольку буферизация чтения усложняет его определение.

У [invalid.txt](data/invalid.txt) ошибочна дата в строке 2. Код — 4.
Строка 1 не должна приводить к частичному успешному отчёту.

## Требования к реализации

- Суммы представлены decimal; при приёме данных точность проверяется, а не молча округляется.
- Есть отдельный тип расхода и методы разбора без чтения Console или файла.
- После успешного создания расход удовлетворяет правилам категории и суммы.
- Файл освобождается при успехе, ошибке данных и ошибке чтения.
- Для группировки используется Dictionary, для порядка вывода — явная сортировка.
- Нет подавления nullable-предупреждений с помощью `!` без объяснённого инварианта.
- При максимальном количестве записей расчёт остаётся в допустимом диапазоне decimal.

## Минимальные сценарии приёмки

| Вход или изменение | Ожидание |
| --- | --- |
| Основной файл | Точный отчёт выше |
| Пустой файл и только пробелы | count=0, total=0.00 |
| `food` и `FOOD` | Одна категория |
| Две одинаковые строки | Два расхода |
| Сумма 0.01 и 999999.99 | Обе принимаются |
| 0, −1, 1000000, 1.234, 1,50 | Код 4, номер строки |
| 2024-02-29 / 2026-02-29 | Первая дата допустима, вторая нет |
| Пустая категория, 33 символа, буква вне ASCII | Код 4 |
| Четвёртое поле | Код 4 |
| Пустая строка перед ошибочной | Учитывается в номере ошибки |
| 100000 / 100001 записей | Успех / код 4 |
| UTF-8 BOM / неверный байт UTF-8 | Успех / код 4 |
| Несуществующий файл | Код 3 |
| Нет аргумента / два аргумента | Код 2 |
| Разные системные культуры | Одинаковый отчёт |

## Как проверить и сдать

Соберите свою программу в Release. Выполните:

```powershell
python tools/verify.py --ledger-dll work/ExpenseLedger/bin/Release/net10.0/ExpenseLedger.dll
```

Без параметра скрипт проверяет готовые примеры курса и их сборку.
Подготовьте исходники, команду запуска и запись трёх найденных вами дефектов с причиной.
Минимум для зачёта: контракт выполнен полностью, все проверки пройдены, код объясним без образца.

Оценка из 10: корректность 4; граничные случаи и ошибки 2; декомпозиция и инварианты 2;
воспроизводимость и ясность 2. Даже при хорошей сумме баллов ошибка денежного расчёта,
частичный отчёт при сбое или неосвобождённый ресурс требуют исправления.
