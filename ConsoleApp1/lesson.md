# Урок по базовым понятиям из переписки

## Рабочее пространство Visual Studio
- **Структура проекта**: Visual Studio создаёт `.csproj` с настройками сборки, `Program.cs` как точку входа, а каталоги `bin/` и `obj/` содержат результаты и промежуточные артефакты компиляции.
- **Назначение директорий**: `bin/` хранит исполняемые файлы (Debug/Release), `obj/` — кеш MSBuild. Они пересоздаются автоматически, поэтому вручную редактировать их не нужно.

## Разбор Program.cs построчно
```csharp
using System;                 // подключаем пространство имён, чтобы использовать Console

namespace MyApp               // логическая «папка» для типов
{
    internal class Program    // тип виден только внутри сборки
    {
        static void Main(string[] args) // точка входа CLR
        {
            Console.WriteLine("Hello, World!"); // вывод строки
        }
    }
}
```
- Скобки образуют области: namespace → class → method. Каждый блок должен корректно закрываться, иначе компилятор выдаёт `CS1513` (требуется `}`).

## Ключевые концепции C#

### `static`
- Принадлежит типу, а не объекту. CLR вызывает `Program.Main` без создания экземпляра.
- Статический метод не может обращаться к нестатическим членам без объекта.

### Создание объектов и вызов методов
- `new Program1()` создаёт экземпляр и возвращает ссылку.
- Метод вызывается на объекте: `new Program1().func1()` либо через переменную `var p = new Program1(); p.func1();`.
- `new Program1.func1()` неверно: после `.` ожидается тип, а не метод, что приводит к `CS0426`.

### Модификатор `internal`
- Доступен только внутри текущей сборки. Внешние проекты не увидят такие классы и методы, если только не использовать `InternalsVisibleTo`.

### Пространства имён
- Группируют типы и предотвращают конфликты имён (`MyApp.Program` vs `OtherLib.Program`).
- В одном файле можно объявлять несколько namespace, допускаются вложенные.

### `var` против `dynamic`
- `var` — вывод статического типа на этапе компиляции. Тип фиксируется по правой части выражения.
- `dynamic` переносит проверку членов на рантайм, удобно для COM/JSON, но теряется безопасность типов и подсказки IDE.

## Обработка ошибок и исключения

### Чтение сообщений компилятора
- Формат: `файл(строка,столбец,...) error CSxxxx: описание`.
- Пример `Program.cs(51,2,51,2): error CS1513` означает, что на строке 51 компилятор ожидал `}`.

### Try/Catch/Throw
- `throw new InvalidOperationException("...");` вручную создаёт исключение в `try`.
- `throw;` без аргумента допустим только внутри `catch` для повторного проброса.
- После выполнения `throw` код ниже не выполняется; управление передаётся в `catch`/`finally` или вверх по стеку.
- Если исключение перехвачено и не выброшено заново, процесс завершается с кодом 0 (успех). Чтобы приложение упало с ошибкой, нужно либо не ловить исключение, либо повторно его выбросить в `catch`.

### Обработка в примере
```csharp
public void Except(dynamic a, dynamic b)
{
    try
    {
        if (a != b)
            throw new InvalidOperationException("Values are not equal");

        Console.WriteLine("YES");
    }
    catch (Exception ex)
    {
        Console.Error.WriteLine("Values are not equal: {0}", ex.Message);
        throw; // если ошибка должна «упасть» до Main
    }
}
```
- Важно возвращать значения в методах, объявленных с типом (`int`). Иначе получим `CS0161`.
- `Console.Error` — это поток `TextWriter`, поэтому нужно вызывать `WriteLine`, а не `Console.Error(...)`.

## Работа с методами и модификаторами
- Каждый метод объявляется отдельно: нельзя вынести `public` над блоком и сделать несколько методов публичными одновременно.
- Можно создавать дополнительные методы (например, `summ`, `except`), но следи за корректной сигнатурой и возвращаемыми значениями.

## Подключение библиотек
- Стандартный путь — через NuGet: «Manage NuGet Packages…» в Visual Studio или команда `dotnet add package PackageName`.
- После установки библиотека прописывается в `.csproj`; в коде остаётся добавить `using` нужного пространства имён.
- Для сторонних DLL используем «Add Reference…» или прописываем ссылку в проекте вручную.

## Типичные ошибки из переписки
- `CS0426` — попытка обратиться к несуществующему вложенному типу (`Program1.func1` вместо создания объекта).
- `CS1513` — незакрытая фигурная скобка.
- `CS0156` — `throw;` вне `catch`.
- Отсутствие `return` в методе, объявленном как `int`, приводит к `CS0161`.
- `Console.Error("...")` — неправильное использование потока ошибок.

## Итоги
1. Следи за структурой файлов: каждый `namespace`/`class`/`method` требует парных скобок.
2. Используй `static` только там, где метод/поле принадлежит типу, а не конкретному объекту.
3. Различай `var` (компилятор выводит тип) и `dynamic` (проверки в рантайме).
4. При обработке исключений решай, должен ли процесс завершиться успешно или с ошибкой.
5. При подключении библиотек через NuGet обновляй `using` в коде и следи за зависимостями в `.csproj`.

Такой конспект поможет быстро вспомнить ключевые моменты, обсуждённые в ходе изучения C# на примере простого консольного приложения.
