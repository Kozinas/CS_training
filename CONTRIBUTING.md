# Как развивать методичку C#

Сначала наполняйте следующий блок из [PLAN](PLAN.md), затем обновляйте статус в [PROGRESS](PROGRESS.md).
Сохраняйте последовательность зависимостей: упражнение не должно требовать ещё не объяснённую технику
без короткого введения. Пишите самостоятельные объяснения, не перепечатывайте книги.

## Добавление главы

1. Создайте Markdown в тематическом каталоге docs. Один H1; подразделы H2/H3.
2. Добавьте цель, необходимые знания, теорию, разобранный пример, ошибки и задачи A/B/C.
3. Для каждой задачи укажите входные данные, ожидаемый результат и критерий готовности.
4. Добавьте или расширьте пример в examples и укажите проверяемые команды.
5. Добавьте страницу в book.json в нужном месте. Все учебные Markdown в docs и labs должны быть перечислены.
6. Обновите language-map, PROGRESS, область охвата scope и дату edition в book.json.
7. Выполните команды ниже, проверьте несколько страниц нового PDF визуально и обновите VALIDATION.

```text
python tools/book.py toc
python tools/book.py check
python tools/verify.py
python -m unittest discover -s tools/tests -v
python tools/book.py build
python tools/check_pdf.py
```

**Общий PDF обязателен для всех глав**, а не только для первого блока.
Храните одну исходную версию текста в Markdown и пересобирайте dist; не правьте PDF вручную.
Будущую главу нельзя помечать готовой только по существованию файла или записи в плане.

## Формат и ссылки

Поддерживаются CommonMark, таблицы, списки, ссылки и блоки кода.
HTML используйте только для служебных комментариев. Сложные диаграммы требуют отдельного расширения сборщика;
простые схемы сейчас пишутся в блоках text. Не вставляйте неподдерживаемый синтаксис молча.

Ссылки делайте относительными. Внутренние ссылки на учебные страницы превращаются в PDF-переходы;
ссылки на файлы примеров остаются относительными к dist. Для будущего опубликованного сайта можно
добавить отдельный способ разрешения URL, сохранив офлайн-сборку.

Код в книге должен быть читаемым без горизонтальной прокрутки; длинные выражения лучше переносить
в исходном Markdown вручную. Опасные или намеренно ошибочные примеры явно помечайте.

## Источники и проверки

Семантику языка сверяйте с официальной документацией и компилятором выбранной версии.
Для стороннего пакета укажите точную проверенную версию и официальный источник.
При изменении версии языка или runtime обновите настройки примеров, требования и проверку совместимости.

Не включайте личные решения work, локальное окружение Python, bin/obj или Books в выпускаемые артефакты курса.
Готовые dist/csharp.pdf и dist/csharp.md содержат только написанный учебный материал и программу.
