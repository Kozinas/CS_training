# 22. Структура исходников и инструменты компилятора

**Результат:** вы организуете объявления и запускаете собственный анализатор и incremental generator
с проверкой полученной сборки. Нужны главы 13, 19 и 21.
Полный пример — [CompilerLab](../../examples/CompilerLab/Program.cs).

## Имена и область видимости

File-scoped namespace `namespace Course.Domain;` действует на оставшуюся часть файла
и заменяет внешние фигурные скобки namespace. Не смешивайте обе формы в одном файле.
Он не превращает папку в namespace автоматически.

| Запись | Действие |
| --- | --- |
| using System.Text; | Позволяет использовать короткие имена типов namespace |
| global using System.Text; | Делает импорт доступным во всей компиляции |
| using static System.Math; | Позволяет писать Sqrt без имени типа |
| using Money = Course.Ledger.Core.Money; | Даёт локальный alias, не новый тип |
| file sealed class Helper | Ограничивает вспомогательный тип текущим файлом |
| extern alias Legacy; | Различает ссылки на сборки с конфликтующими именами |

extern alias требует настроить alias у ProjectReference/Reference; один текст объявления
не создаёт ссылку на сборку. Обращение имеет вид `Legacy::Vendor.Type`.
Это инструмент интеграции несовместимых API, а не обычная замена namespace.
ImplicitUsings SDK создаёт global using в obj: проверьте этот файл, если имя доступно без явного импорта.

## partial связывает рукописный и сгенерированный код

Части partial-типа принадлежат одной компиляции и одному типу.
Это не способ дописать закрытую библиотеку после её выпуска.
В простом генераторе пользователь объявляет часть BuildInfo с вычисляемой Length,
а генератор добавляет Title в другую часть.

Partial-метод с необязательной реализацией имеет ограничения:
без модификатора доступа, void, без out и ряда модификаторов виртуальности.
При отсутствии реализации компилятор удаляет и вызовы, включая вычисление их аргументов.
Если нужен обязательный результат, объявите явный доступ и реализацию.
С C# 13 есть partial properties/indexers, с C# 14 — instance constructors/events.
Их определяющая и реализующая части должны согласоваться; partial не разрешён у static constructor.
[Правила partial-членов](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/keywords/partial-member).

В RuntimeLab файлы Modern.cs и Modern.Implementation.cs демонстрируют property, constructor и event.
Команда главы 24 проверяет совместное поведение. Выбирайте разделение ради генерации или понятной
границы ответственности; дробление каждого метода по файлам не упрощает тип само по себе.

## Директивы и документация

Директивы обрабатываются до обычного выполнения. `#define TRACE_INPUT` задаёт символ,
а не текстовый макрос. `#if TRACE_INPUT`, `#else`, `#endif` включают разные участки исходника.
Символ можно задавать в DefineConstants; DEBUG определяется конфигурацией сборки.

| Директива | Когда нужна |
| --- | --- |
| #nullable enable/restore | Постепенное включение null-анализа |
| #pragma warning disable/restore CSxxxx | Узкое обоснованное подавление предупреждения |
| #line | Отображение сгенерированных строк на исходный документ |
| #error / #warning | Диагностика недопустимой конфигурации |
| #region / #endregion | Сворачивание в редакторе, без изменения исполнения |

Не прячьте обычное ветвление приложения за #if, если решение должно приниматься по входным данным.
После миграции убирайте временные подавления, иначе новый дефект окажется невидимым.

XML-комментарии `/// <summary>...` описывают API; param, returns, exception и cref связывают
его с параметрами и типами. GenerateDocumentationFile создаёт XML при сборке.
Документируйте правила: владение Stream, допустимость null, порядок результата, исключения.
Повторение «возвращает значение» не объясняет контракт.

## Syntax tree, semantic model и operations

Roslyn представляет исходник как дерево синтаксиса с токенами и trivia: пробелами и комментариями.
Строка `Console.WriteLine` сама по себе не доказывает обращение к System.Console.
Имя может быть alias, локальным типом или текстом внутри строки.
SemanticModel связывает узлы с символами типов и методов; IOperation даёт представление операции.

Наш DomainConsoleAnalyzer сообщает COURSE001 для вызовов методов System.Console внутри
namespace Course.Domain и его подпространств. Он регистрирует OperationKind.Invocation,
получает TargetMethod.ContainingType и сравнивает символ с System.Console через
SymbolEqualityComparer.Default.

```csharp
// Фрагмент callback анализатора; invocation — IInvocationOperation.
bool isConsole = SymbolEqualityComparer.Default.Equals(
    invocation.TargetMethod.ContainingType, consoleSymbol);
```

Проверки отличают alias и using static от пользовательского класса Console.
Course.DomainExtra не входит в Course.Domain. Сообщение указывает на место вызова.
Это ограниченное архитектурное правило: оно не ищет доступ к Console.Out как свойству
или косвенную передачу I/O через другой сервис.

Анализатор выдаёт диагностику, но не переписывает код. Code fix — отдельный компонент.
Работа анализатора может быть конкурентной: не храните изменяемое состояние конкретной
компиляции в статических полях.

## Incremental generator

BannerGenerator получает один AdditionalText с именем course.txt.
Сначала фильтрует входы, затем переводит SourceText в строку и собирает результат.
При одном непустом значении выдаёт BuildInfo.g.cs; иначе сообщает COURSE002.
Для строкового литерала используется Roslyn SymbolDisplay.FormatLiteral:
кавычки, переводы строк и обратная косая черта должны сохранять значение.

Incremental API описывает цепочку преобразований. Хост может повторно использовать неизменившиеся
результаты; это не обещание «генератор всегда вызывается ровно один раз».
Не используйте DateTime.Now, случайные значения и чтение файлов мимо входов Roslyn.
Source generator добавляет новые исходники, но не изменяет существующие.
[Рекомендации Roslyn](https://github.com/dotnet/roslyn/blob/main/docs/features/incremental-generators.cookbook.md).

В примере цепочка маленькая: Collect нужен для проверки единственного файла.
Для большого числа независимых элементов сохраняйте поэлементную обработку, где это возможно,
и используйте модели с корректным равенством, чтобы изменение одного входа не пересоздавало всё.

## Запуск и границы учебного хоста

```powershell
dotnet run --project examples/CompilerLab -c Release
```

В выводе есть `PASS CompilerLab`, сообщение об alias и строка
`BuildInfo.g.cs: compiled and executed`.
Хост создаёт компиляцию, запускает analyzer/generator, выполняет Emit в MemoryStream,
загружает сборку в отдельный AssemblyLoadContext и читает Title/Length.
Тест с кавычками и переводом строки проверяет значение, а не только наличие сгенерированного файла.
Unload запрашивает выгрузку контекста; её завершение зависит от отсутствия удерживающих ссылок и GC.

Это **самостоятельный учебный хост**, а не устанавливаемый плагин IDE.
Он ссылается на Microsoft.CodeAnalysis из выбранного SDK через MSBuildSDKsPath:
внешние NuGet-пакеты не нужны, но совместимость связана с SDK.
Для распространяемого analyzer/generator обычно создают отдельную библиотеку под поддерживаемый
хостами target, фиксируют пакеты Roslyn и подключают её как analyzer.
Пример подключения такой отдельной библиотеки:

```xml
<ItemGroup>
  <ProjectReference Include="../MyGenerator/MyGenerator.csproj"
                    OutputItemType="Analyzer"
                    ReferenceOutputAssembly="false" />
  <AdditionalFiles Include="course.txt" />
</ItemGroup>
```

Не подключайте CompilerLab.exe этим способом: он устроен как демонстрационное приложение.
Установка и упаковка расширения для разных IDE в текущий практикум не входят.

## Практика

**22-A.** В копии CompilerLab измените вход на `C# "advanced"`.
Критерий: generated source компилируется, а Title в загруженной сборке совпадает с исходной строкой.

**22-B.** Расширьте COURSE001 запретом чтения Console.Out в Course.Domain.
Входы: обычное обращение, alias, свойство одноимённого пользовательского типа и Course.Ui.
Ожидается диагностика только в первых двух случаях. Критерий: анализируется символ, а не текст.

**22-C.** Добавьте в course.txt вторую строку с целым номером редакции 1–999.
Ожидаются Title и Edition; пустой/нечисловой/нулевой номер даёт понятную диагностику без исходника.
Критерий: проверьте успешный Emit, реальные значения, ошибочные входы и одинаковый результат
повторного запуска на неизменных данных. Готовый генератор реализует только исходный договор.
