# 26. Текст, время и регулярные выражения

**Результат:** вы различаете байты, Unicode и элементы текста, не теряете часовой пояс
и делаете проверки времени воспроизводимыми. Нужны главы 06, 21–23 и 25.
Код — [TextAndTime](../../examples/Integration/BclLab/TextAndTime.cs).

## От байтов к тексту

Encoding переводит байты в кодовые единицы и обратно. UTF-8 относится к внешним байтам,
а string в .NET представлен UTF-16. char содержит одну кодовую единицу, а не обязательно
целый символ Unicode. Поэтому Length не является числом видимых символов.

Rune представляет Unicode scalar value; StringInfo работает с текстовыми элементами.
Для строки `"\U0001F600"` получаются 2 UTF-16 единицы, 1 scalar и 1 элемент.
У `"e\u0301"` — 2 единицы, 2 scalar, но 1 элемент. В методичке используются escape-записи,
чтобы пример не зависел от наличия символа в PDF-шрифте.

Normalize(FormC) приводит канонически эквивалентные последовательности к общей форме:
`"e\u0301".Normalize()` совпадает с `"\u00e9"`.
Нормализация не устраняет все визуально похожие символы разных алфавитов и не заменяет
проверку технического идентификатора. Категории расходов остаются ограничены ASCII.
[Unicode и кодировки](https://learn.microsoft.com/en-us/dotnet/standard/base-types/character-encoding-introduction).

```csharp
var utf8 = new UTF8Encoding(
    encoderShouldEmitUTF8Identifier: false,
    throwOnInvalidBytes: true);
byte[] bytes = utf8.GetBytes("Привет");
string restored = utf8.GetString(bytes);
```

Строгий декодер отклоняет повреждение вместо тихой подстановки заменяющего символа.
При чтении кусками многобайтовая последовательность может пересечь границу буфера:
используйте Decoder или StreamReader, а не независимый GetString для каждого блока.

## Regex решает задачу формы

Регулярное выражение удобно для локального формата, но не заменяет DateOnly.TryParseExact
для проверки существования даты. Якоря `\A` и `\z` означают абсолютные начало и конец;
`$` имеет особенности перед завершающим переводом строки. Проверка не должна принимать
food с лишним переводом строки, если договор запрещает его.

```csharp
// Внутри partial-класса; метод генерирует компилятор.
[GeneratedRegex("\\A[a-z][a-z0-9_-]{0,31}\\z",
    RegexOptions.CultureInvariant, 100)]
public static partial Regex CategoryPattern();
```

Последний аргумент задаёт timeout в миллисекундах. GeneratedRegex подходит для известного
шаблона и позволяет не разбирать его заново при каждом вызове.
NonBacktracking выбирает движок с другими ограничениями и линейным характером обработки;
не все regex-конструкции, например backreference, им поддерживаются.
Не сочетайте режимы в надежде получить все преимущества автоматически.
Для сложных шаблонов ограничивайте также размер входа и обрабатывайте RegexMatchTimeoutException.
[Генератор Regex](https://learn.microsoft.com/en-us/dotnet/standard/base-types/regular-expression-source-generators).

## Выбирайте тип времени по смыслу

| Тип | Что представляет | Чего не содержит |
| --- | --- | --- |
| DateOnly | Календарную дату расхода | Время суток и зону |
| TimeOnly | Время на часах | Дату и зону |
| TimeSpan | Длительность/интервал | Календарное правило «следующий месяц» |
| DateTime | Дату и время с Kind | Полную идентичность часового пояса |
| DateTimeOffset | Время и конкретное смещение | Правила зоны на будущие даты |
| TimeZoneInfo | Правила зоны | Единственный момент без даты/времени |

Для события, случившегося в конкретный момент, обычно храните UTC или DateTimeOffset.
Для «занятие каждый понедельник в 09:00 по местному времени» нужны календарное правило и зона.
Дата расхода в L03 — DateOnly: она не сдвигается на предыдущий день при переводе в UTC,
потому что вообще не является моментом времени.

DateTime.SpecifyKind меняет метку Kind, но не переводит часы между поясами.
Строку обмена разбирайте по явному формату и InvariantCulture; формат `O` полезен для
обмена значениями времени с достаточной точностью.

## Несуществующее и неоднозначное местное время

При переводе часов вперёд часть местных показаний отсутствует; при переводе назад часть встречается дважды.
Нельзя молча угадывать момент. Наш ToInstant принимает DateTimeKind.Unspecified,
отклоняет IsInvalidTime и IsAmbiguousTime, затем использует смещение заданной зоны.
Для неоднозначного ввода можно запросить явный offset либо применить заранее документированную политику.
[Неоднозначное время](https://learn.microsoft.com/en-us/dotnet/standard/datetime/resolve-ambiguous-times).

Чтобы тест не зависел от установленной базы часовых поясов, TrainingZone задаёт учебные правила:
UTC−5 зимой, UTC−4 летом, переходы во второе воскресенье марта и первое воскресенье ноября.
Это искусственная зона для упражнения, не актуальный справочник правил реального региона.

В 2026 году 8 марта 02:30 отсутствует, 1 ноября 01:30 неоднозначно.
15 января 12:00 соответствует 17:00 UTC. Реальные идентификаторы и доступность TimeZoneInfo
проверяйте на целевой ОС; обновления правил зон требуют обновлений окружения.

## Время как зависимость

TimeProvider позволяет передать источник времени вместо скрытого DateTimeOffset.UtcNow.
В проверках FixedClock всегда возвращает выбранный момент, поэтому граница истечения проверяется
без Thread.Sleep. Договор IsExpired: истекло при `now >= created + lifetime`.
Для измерения длительности обработки используйте timestamp/elapsed time, а не разность
показаний настенных часов, которые могут быть скорректированы.

TimeProvider не ускоряет любой Task.Delay автоматически. Для управления таймерами нужны
API, принимающие соответствующий provider; это будет важно в async-блоке.

## Культура, ресурсы и случайность

CurrentCulture отвечает за форматы чисел/дат и некоторые сравнения;
CurrentUICulture участвует в выборе локализованных ресурсов.
BclLab содержит Messages.resx и Messages.ru.resx.
ResourceManager для ru-RU находит ru, а для en-US при отсутствии отдельного ресурса использует базовый.
Не используйте отображаемый перевод строки как ключ хранилища.

Guid.NewGuid даёт идентификатор; уникальность данных всё равно подтверждается правилом хранилища.
Random подходит для моделирования и несекретной случайности; Random.Shared удобен для общего
потокобезопасного генератора. Seed полезен в тесте, но точную последовательность между версиями
реализации не считайте форматом хранения.
Для секретного случайного значения используйте RandomNumberGenerator, например GetBytes.
Идентификатор и секрет — разные договоры.
[Назначение Random](https://learn.microsoft.com/en-us/dotnet/api/system.random?view=net-10.0).

```powershell
dotnet run --project examples/Integration/BclLab -c Release -- 26
python tools/verify_integration.py
```

Вывод: True; 2,1,1; True; 2026-01-15T17:00:00.0000000+00:00; True; True.
Проверки отдельно проверяют ресурсы, invalid/ambiguous time и точную границу истечения.

## Практика

**26-A.** Сравните Length, Rune-count и StringInfo для `"abc"`, `"\U0001F600"`,
`"e\u0301"`. Ожидаются 3/3/3, 2/1/1 и 2/2/1. Критерий: объяснены три разных единицы измерения.

**26-B.** Импортируйте три местных времени TrainingZone из примера.
Ожидается один момент UTC и две отдельные ошибки: nonexistent и ambiguous.
Критерий: результат не зависит от локальной зоны компьютера; UTC-Kind на входе отклонён.

**26-C.** Сделайте локализованный отчёт о сроке действия импорта: сообщения ru/en,
срок 10 минут и передаваемый TimeProvider.
Через 9 минут 59 секунд после создания ещё действителен, ровно через 10 минут истёк.
Критерий: тесты не спят, машинные даты остаются invariant, пользовательский текст берётся из ресурсов.
