# 25. Коллекции и алгоритмы BCL

**Результат:** вы выбираете структуру по операциям, задаёте сравнение и проверяете порядок работы.
Нужны главы 07, 12–16 и 23. Примеры нового блока находятся в
[Integration](../../examples/Integration/README.md); первый restore загружает закреплённые пакеты.

## Начните с операций

BCL — стандартная библиотека платформы. Коллекция не должна выбираться только по привычке.
Сначала перечислите требования: доступ по позиции, поиск по ключу, удаление, сортированный обход,
снимки, конкуренция. Запись O(n) означает, что работа растёт примерно с числом элементов;
O(log n) — значительно медленнее, O(1) — не зависит от n в рассматриваемой модели.

| Структура | Подходящая задача | Стоимость и ограничение |
| --- | --- | --- |
| Array / List | Индексация, последовательный проход | Индекс O(1), поиск без индекса O(n) |
| Dictionary | Получить запись по Id | В среднем O(1); важны хеш и равенство |
| HashSet | Проверить уникальность | В среднем O(1); нет значений по ключам |
| SortedDictionary / SortedSet | Упорядоченный обход и обновления | Обычно O(log n) на поиск/вставку |
| SortedList | Компактный отсортированный словарь | Бинарный поиск; вставка со сдвигом O(n) |
| Queue / Stack | FIFO / LIFO | Порядок извлечения — часть договора |
| PriorityQueue | Взять наиболее срочную работу | Вставка/извлечение O(log n), минимум приоритета первым |
| LinkedList | Вставка рядом с известным узлом | O(1) при наличии узла; поиск узла O(n) |

Ёмкость Capacity у List — зарезервированное место, Count — число элементов.
Увеличение ёмкости может копировать буфер. Если размер известен, задайте разумную начальную Capacity;
не выделяйте память прямо по неограниченному числу из входного файла.
[Выбор generic-коллекций](https://learn.microsoft.com/en-us/dotnet/standard/collections/when-to-use-generic-collections).

## Интерфейс описывает возможности

IEnumerable обещает перечисление, ICollection добавляет Count и операции коллекции,
IList — индекс. IReadOnlyCollection и IReadOnlyList запрещают изменение через данный интерфейс,
но не гарантируют неизменяемость объекта и не делают снимок.

List.AsReadOnly выдаёт живое представление: изменение исходного List видно потребителю.
L02 требовала снимок, поэтому копировала данные. Даже immutable-контейнер не делает
изменяемые объекты-элементы глубоко неизменяемыми.
Возвращайте наиболее узкий интерфейс, который выражает договор, но не скрывайте стоимость:
IEnumerable может означать повторное вычисление или чтение внешнего источника.

## Два вида сравнения

IEqualityComparer определяет равенство и хеширование для Dictionary/HashSet.
IComparer определяет порядок для сортировки и sorted-коллекций.
У SortedSet сравнение, вернувшее 0, означает одинаковый элемент множества,
даже если Equals самих объектов возвращает false.

```csharp
var categories = new SortedSet<string>(
    StringComparer.OrdinalIgnoreCase) { "food", "FOOD", "travel" };
Console.WriteLine(categories.Count); // 2
```

Для технических ключей выбирайте явное ordinal-сравнение либо нормализуйте ключ на границе,
как в Expense. Не меняйте поля ключа, участвующие в Equals/GetHashCode, пока ключ находится в словаре.
Для отображения человеку правило культуры может быть другим.
Изменение comparer меняет смысл данных: это отдельное требование, а не косметический рефакторинг.

## Очередь с устойчивым порядком

PriorityQueue сама не гарантирует FIFO для одинаковых приоритетов.
Чтобы два равноприоритетных задания выполнялись по порядку поступления, добавим sequence.
Tuple сравнивается лексикографически: сначала Priority, затем Sequence.

```csharp
var queue = new PriorityQueue<string, (int Priority, long Sequence)>();
queue.Enqueue("later", (2, 0));
queue.Enqueue("first", (1, 1));
queue.Enqueue("second", (1, 2));
while (queue.TryDequeue(out string? job, out _))
    Console.WriteLine(job);
```

Результат: first, second, later. Счётчик sequence принадлежит владельцу очереди;
его переполнение и конкурентная выдача номеров требуют отдельной политики.
Не изменяйте приоритет поля уже добавленного объекта с ожиданием автоматической перестройки очереди.
[Договор PriorityQueue](https://learn.microsoft.com/en-us/dotnet/api/system.collections.generic.priorityqueue-2?view=net-10.0).

## Поиск, сортировка и неизменяемые данные

Array.Sort/List.Sort меняют контейнер и не обещают устойчивость равных элементов.
OrderBy создаёт отложенный LINQ-запрос со стабильной сортировкой.
BinarySearch корректен только на данных, отсортированных совместимым comparer.
При отсутствии элемента возвращается отрицательное число; побитовое дополнение `~index`
даёт позицию вставки, а не просто абсолютное значение результата.

Immutable-коллекции создают новую версию при Add/Remove и могут разделять внутренние структуры.
Храните возвращённый результат: вызов Add без присваивания не меняет прежний объект.
FrozenDictionary/FrozenSet рассчитаны на построение и последующие частые чтения;
стоимость создания нужно окупить. Они не заменяют Dictionary, который постоянно обновляется.

ConcurrentDictionary/ConcurrentQueue предоставляют отдельные потокобезопасные операции.
Последовательность «ContainsKey, затем Add» от этого не становится атомарной.
Используйте подходящую единую операцию, например TryAdd. Фабрика GetOrAdd может быть вызвана
несколько раз при конкуренции: не помещайте в неё необратимую оплату или отправку сообщения.
Полная модель потоков появится в главе 32.

## Большие числа и generic math

BigInteger хранит целое число произвольной практической длины, ограниченной памятью.
Это не decimal для денежных дробей и не бесплатное расширение Int64: арифметика дорожает
с ростом числа разрядов.

INumber и более узкие числовые интерфейсы позволяют выразить generic-алгоритм без dynamic.
В [NumberAlgorithms](../../examples/Integration/BclLab/NumberAlgorithms.cs) сумма использует
T.Zero и checked-сложение. Для int проверяется переполнение, для BigInteger обычного фиксированного
верхнего предела нет. Алгоритм остаётся зависимым от семантики выбранного T:
float по-прежнему имеет округление и специальные значения.
[Generic math](https://learn.microsoft.com/en-us/dotnet/standard/generics/math).

```powershell
dotnet run --project examples/Integration/BclLab -c Release -- 25
python tools/verify_integration.py
```

После трёх имён очередь выводит `2,3` — длины исходной и новой immutable-версий,
`2` — поиск FOOD в frozen-словаре, и `1267650600228229401496703205376` — 2 в степени 100.

## Практика

**25-A.** Добавьте в очередь задачи A(1), B(1), C(0), D(2).
Ожидается C,A,B,D. Критерий: порядок равных приоритетов задан sequence, а не случайно совпал.

**25-B.** Для категорий food, FOOD, travel построите регистронезависимый индекс количеств.
Ожидается два ключа и food=2. Затем создайте неизменяемый снимок.
Критерий: последующее обновление исходного словаря не меняет значения снимка.

**25-C.** Создайте очередь импорта с поиском задания по Guid и выбором по приоритету.
Определите договор повторного Id и отмены задания до извлечения.
Критерий: тесты покрывают пустую очередь, равные приоритеты, повтор, отмену и 1000 заданий;
объяснено, почему одного списка недостаточно для выбранных операций.
Многопоточность пока не требуется.
