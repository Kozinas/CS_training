# 16. LINQ в памяти и в запросах

**Результат:** вы формулируете преобразование данных, предсказываете момент его выполнения и
различаете IEnumerable и IQueryable. Нужны главы 13–15.
Запуск: `dotnet run --project examples/TypesAndQueries -- 16`.

## Конвейер данных

LINQ связывает операции над последовательностями. Он не заменяет понимание количества проходов,
выделения памяти или правил сравнения.

```csharp
int[] values = [5, 1, 4, 2];
IEnumerable<int> query = values
    .Where(static n => n % 2 == 0)
    .Select(static n => n * 10)
    .OrderBy(static n => n);

Console.WriteLine(string.Join(",", query)); // 20,40
```

Where отбирает, Select преобразует, OrderBy упорядочивает. Это extension methods:
namespace System.Linq должен быть подключён, в проектах курса он входит в implicit usings.
Query syntax выражает часть тех же операций:

```csharp
var query =
    from n in values
    where n % 2 == 0
    orderby n
    select n * 10;
```

Это альтернативное объявление query, а не ещё одна переменная с тем же именем в той же области.
Компилятор переводит форму запроса в вызовы методов. Выберите форму, в которой намерение яснее;
короткая цепочка не обязана становиться большим query expression.

## Когда запрос выполняется

| Операция в LINQ to Objects | Выполнение | Что учитывать |
| --- | --- | --- |
| Where, Select, Take | Отложенное, обычно по одному элементу | Источник читается при обходе |
| OrderBy, GroupBy | Отложенное, с накоплением данных | Для полного упорядочения/группировки нужен весь вход |
| ToList, ToArray, ToDictionary | Немедленное | Создаётся материализованный результат |
| Sum, Count, Any, First | Терминальное | Возвращает значение; некоторые умеют заканчивать раньше |

```csharp
List<int> values = [1, 2];
var query = values.Where(static x => x > 1);
values.Add(3);
Console.WriteLine(string.Join(",", query)); // 2,3
int[] snapshot = query.ToArray();
values.Add(4);
Console.WriteLine(string.Join(",", snapshot)); // 2,3
```

Это отдельный полный фрагмент. Query описывает вычисление, snapshot хранит его результат.
Повторное перечисление может повторить чтение файла или работу API.
Не помещайте обязательные побочные действия в Select: оптимизации некоторых терминальных операций
способны получить результат без исполнения всех селекторов. Действие выполняйте явным циклом.

## Выбор результата

| Метод | Пустая последовательность | Несколько совпадений |
| --- | --- | --- |
| First | Исключение | Первое |
| FirstOrDefault | Default или явно заданный fallback | Первое |
| Single | Исключение | Исключение |
| SingleOrDefault | Default | Исключение |
| Any | false | true после обнаружения элемента |
| All(predicate) | true | Проверка всех до первого false |

Single выражает проверяемое обещание уникальности. First не доказывает уникальность.
Default может быть нормальным значением: FirstOrDefault для int возвращает 0 и при отсутствии,
и когда первым элементом действительно был 0. Уточняйте контракт или выбирайте nullable/result.

Sum для пустого набора decimal даёт 0; Average для пустого набора non-nullable decimal бросает исключение.
Aggregate с начальным значением работает и на пустом входе; без него требует хотя бы один элемент.
Проверяйте крайние случаи для конкретного overload, особенно при nullable-значениях.

## Группировка и сортировка отчёта

```csharp
// entries — IEnumerable<Expense> из L02.
var totals = entries
    .GroupBy(static e => e.Category, StringComparer.Ordinal)
    .Select(static group => new
    {
        Category = group.Key,
        Total = group.Sum(static e => e.Amount.Amount)
    })
    .OrderBy(static row => row.Category, StringComparer.Ordinal)
    .ToArray();
```

Category уже нормализована в модели. Anonymous type здесь удобен для локальной проекции;
для публичного результата библиотека использует именованный CategoryTotal.
В `e.Amount.Amount` первое Amount — Money расхода, второе — его числовое значение.

ThenBy добавляет вторичный критерий. Новый OrderBy на уже упорядоченном запросе начинает новое
основное упорядочение; это частая причина потери первого критерия.
Для воспроизводимости задавайте все необходимые критерии, включая порядок при равенстве.

## Соединение и плоская последовательность

SelectMany разворачивает последовательность вложенных последовательностей.
Например, дни с массивами расходов можно преобразовать в один поток расходов.
Join сопоставляет элементы по ключу и возвращает все совпадающие пары; дубликаты ключей
могут умножить число строк. GroupJoin возвращает левый элемент вместе с группой совпадений.

Для внешнего соединения нужны также строки без совпадения: классическая форма использует
GroupJoin, DefaultIfEmpty и SelectMany. Начиная с .NET 10 существуют также
[LeftJoin](https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.leftjoin?view=net-10.0)
и [RightJoin](https://learn.microsoft.com/en-us/dotnet/api/system.linq.enumerable.rightjoin?view=net-10.0);
в старой целевой платформе этих API может не быть. Семантику SQL и null разберём в блоке БД.

Distinct и DistinctBy устраняют повторы по равенству или выбранному ключу;
они не доказывают корректность отброшенных повторов. Chunk группирует вход в массивы указанного размера,
последний может быть короче. ToDictionary отклоняет повторные ключи, поэтому это не операция группировки.

## IEnumerable и IQueryable

Enumerable принимает обычные делегаты и выполняет код .NET над элементами.
Queryable часто принимает `Expression<Func<T, bool>>`: дерево описания выражения.
Провайдер, например EF Core, переводит поддерживаемые части в запрос к БД.

Не любой C#-метод можно перевести в SQL. AsEnumerable переключает последующие операции
на обычное перечисление и не материализует всё немедленно, но может перенести фильтрацию
на клиент и увеличить объём получаемых данных. ToList немедленно выполняет запрос.
Порядок, сравнение строк и null зависят от конкретного провайдера; опыт LINQ в памяти
не заменяет проверку SQL, который реально отправлен серверу.

## Практика

**16-A.** Для 5,1,4,2 получите 20,40; для пустого входа — пустой результат.
Сделайте методическую и query-форму. Критерий: одинаковый порядок и значения.

**16-B.** Для food=12.50, travel=30, food=7.50 получите food=20.00 и travel=30.00.
Критерии: порядок категорий явно определён, пустой набор даёт пустой отчёт,
повтор food входит в сумму и не теряется через DistinctBy.

**16-C.** Воспроизведите изменение отложенного результата после Add.
Затем поставьте ToArray на нужной границе. Критерий: сохранённый отчёт не меняется.
Дополнительно объясните, почему Any()+foreach может дважды обратиться к источнику.
