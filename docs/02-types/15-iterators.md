# 15. Перечисление и итераторы

**Результат:** вы отличаете рецепт перечисления от готовой коллекции и освобождаете ресурсы
при досрочном прекращении чтения. Нужна глава 14.
Запуск: `dotnet run --project examples/TypesAndQueries -- 15`.

## Что происходит в foreach

`IEnumerable<T>` предоставляет GetEnumerator. Перечислитель `IEnumerator<T>` хранит позицию:
MoveNext перемещается к следующему элементу, Current даёт текущий.
Не читайте Current до первого успешного MoveNext или после конца последовательности.

Упрощённая модель foreach:

```csharp
using IEnumerator<int> iterator = values.GetEnumerator();
while (iterator.MoveNext())
{
    int value = iterator.Current;
    Console.WriteLine(value);
}
```

Это фрагмент для переменной `IEnumerable<int> values`.
Настоящий foreach также поддерживает подходящий pattern GetEnumerator/MoveNext/Current
без обязательного объявления интерфейса и имеет специальные варианты для некоторых типов.
Основная мысль: он последовательно запрашивает элементы и освобождает перечислитель по правилам конструкции.

Негeneric IEnumerator.Current возвращает object, что может вызвать boxing.
Generic-вариант сохраняет статический тип элемента. Перечислитель не обещает потокобезопасность
и обычно не допускает произвольного изменения исходной коллекции во время обхода.

## Yield создаёт машину состояний

```csharp
static IEnumerable<int> Countdown(int start)
{
    for (int value = start; value > 0; value--)
    {
        yield return value;
    }
}
```

Вызов Countdown(3) ещё не выполняет тело цикла до конца.
При MoveNext выполнение продолжается до ближайшего yield return, который выдаёт элемент и
приостанавливает метод. Локальные переменные и место продолжения сохраняются сгенерированным объектом.
Yield break заканчивает перечисление; достижение конца тела делает то же самое.

`var numbers = Countdown(3);` хранит последовательность. Два foreach обычно запускают два обхода:
3,2,1 и снова 3,2,1. Сам интерфейс IEnumerable не гарантирует повторяемость:
пользовательский источник может читать меняющиеся данные или разрешать только один проход.

## Когда выполняется проверка

```csharp
static IEnumerable<int> PositiveRange(int count)
{
    if (count < 0)
    {
        throw new ArgumentOutOfRangeException(nameof(count));
    }
    return Iterate(count);

    static IEnumerable<int> Iterate(int count)
    {
        for (int i = 0; i < count; i++)
        {
            yield return i + 1;
        }
    }
}
```

Внешний метод не является итератором: у него нет yield. Поэтому он проверяет count сразу.
Если поместить проверку непосредственно в метод с yield, она выполнится только при начале обхода.
Разница важна для понятного контракта и выбора границ try/catch.

Методы-итераторы не могут иметь ref/out/in параметры. Yield нельзя поместить в catch или finally,
а yield return — в try с catch. Try с finally допустим. Новые версии языка расширяли правила
для ref/unsafe рядом с итераторами; их ограничения и сохранение значений через yield изучаются в главе 23.

## Ресурс принадлежит перечислению

```csharp
static IEnumerable<string> ReadLines(string path)
{
    using StreamReader reader = new(path);
    string? line;
    while ((line = reader.ReadLine()) is not null)
    {
        yield return line;
    }
}
```

Это обычное текстовое чтение; строгий UTF-8 из L01 при необходимости настраивается дополнительно.
Файл открывается при начале обхода. Using остаётся активным между выдачами строк.
Когда foreach завершится нормально или через break, Dispose перечислителя выполняет нужное finally
и закрывает reader. Если вручную получить перечислитель и забыть Dispose, ресурс может удерживаться.

Опасный вариант — открыть reader в обычном внешнем методе внутри using, вернуть ленивую
последовательность на его основе и сразу выйти. К началу обхода reader уже закрыт.
Ресурс должен жить столько же, сколько выполняется работа с ним.

## Lazy, eager и бесконечные источники

Ленивый источник производит элементы по запросу. Материализация, например
`new List<int>(numbers)`, выполняет весь обход и сохраняет результат.
Она расходует память, зато даёт собственный набор для повторной работы.

Бесконечный источник можно обработать только с условием остановки.
Не пытайтесь материализовать его целиком. Даже ленивый алгоритм может зависнуть, если запрос
требует конца источника: например, подсчёт всех элементов.

`IAsyncEnumerable<T>` и await foreach добавляют асинхронное ожидание очередного элемента.
Они не означают автоматическую параллельную обработку. Отмена и освобождение через await using
рассматриваются после Task в главе 31.

## Практика

**15-A.** Напишите Countdown и выведите первые два элемента через foreach с break.
Критерии: для 3 выводятся 3 и 2; для 0 последовательность пуста.
Добавьте finally с диагностикой и убедитесь, что оно выполняется при break.

**15-B.** Сделайте PositiveRange с немедленной проверкой count.
Критерий: PositiveRange(-1) бросает исключение до GetEnumerator.
Для 3 получаются 1,2,3, для 0 — пустая последовательность.

**15-C.** Создайте источник со счётчиком выданных элементов. Обойдите его дважды,
затем один раз материализуйте и дважды обойдите список.
Критерий: в первом случае генерация повторяется, во втором повторно обходятся сохранённые значения.
Покажите, где освобождается файл при break в файловом варианте.
