# 14. Делегаты, лямбды и события

**Результат:** вы передаёте поведение как аргумент, понимаете захват переменных и управляете подписками.
Нужны главы 11–13. Запуск: `dotnet run --project examples/TypesAndQueries -- 14`.

## Функция как значение

Делегат хранит вызываемый метод и при необходимости его целевой объект.
Тип делегата определяет параметры и результат.

```csharp
Func<decimal, bool> isLarge = amount => amount >= 1000m;
Console.WriteLine(isLarge(1200m)); // True

static bool IsPositive(decimal amount) => amount > 0m;
Func<decimal, bool> isPositive = IsPositive; // method group
```

Func имеет результат последним параметром типа; Action возвращает void;
`Predicate<T>` принимает T и возвращает bool. Можно объявить собственный тип,
например `delegate decimal Discount(decimal price);`, если предметное имя помогает понять API.

Лямбда `amount => amount >= 1000m` — короткое описание поведения.
Блочное тело `amount => { return amount >= 1000m; }` позволяет несколько инструкций.
Анонимный метод `delegate(decimal amount) { return amount > 0m; }` — более старый синтаксис.
Если преобразование лямбды задаёт expression tree, результатом будет описание выражения,
а не обычный готовый делегат; это понадобится для IQueryable.

## Захват переменной

```csharp
decimal limit = 100m;
Func<decimal, bool> exceeds = value => value > limit;
limit = 200m;
Console.WriteLine(exceeds(150m)); // False
```

Замыкание захватывает переменную, а не фиксирует её значение на момент объявления.
Если нужен снимок, создайте отдельную переменную и больше её не изменяйте.
Захваченные объекты могут жить дольше метода, который создал лямбду.

Распространённая ловушка — переменная for:

```csharp
List<Action> actions = [];
for (int i = 0; i < 3; i++)
{
    actions.Add(() => Console.WriteLine(i));
}
foreach (Action action in actions)
{
    action(); // 3, 3, 3
}
```

Для независимых значений создайте `int captured = i;` внутри тела и захватывайте captured.
В современном C# переменная foreach имеет отдельный экземпляр для каждой итерации;
не переносите без проверки старые объяснения этого поведения.

Static-лямбда, например `static amount => amount > 0m`, не захватывает окружение.
Это выражает намерение и предотвращает случайное удержание объекта, но само по себе
не обещает нулевых выделений памяти во всех ситуациях.

## Список вызовов

Делегаты поддерживают += и -=, образуя список обработчиков.
Они вызываются последовательно, в порядке добавления. Исключение одного обработчика
по обычным правилам прекращает вызов следующих. Для делегата с результатом обычный вызов
возвращает результат последнего обработчика, а не список всех результатов.

Поэтому цепочку обработчиков не следует использовать как неявный механизм транзакций
или накопления результатов. Если нужно собрать ответы или независимо обработать ошибки,
опишите алгоритм вызова явно.

## Event ограничивает доступ

```csharp
public sealed class Counter
{
    public event EventHandler? Changed;
    public int Value { get; private set; }

    public void Increment()
    {
        Value++;
        Changed?.Invoke(this, EventArgs.Empty);
    }
}
```

Снаружи можно подписаться и отписаться, но нельзя присвоить событию произвольный список
или поднять его обычным вызовом. Внутри владельца field-like event ведёт себя как делегат.
`EventHandler<TEventArgs>` передаёт данные уведомления; в L02 это созданный Expense.

```csharp
// Фрагмент после создания Counter.
Counter counter = new();
int notifications = 0;
EventHandler handler = (_, _) => notifications++;
counter.Changed += handler;
counter.Increment();
counter.Changed -= handler;
counter.Increment();
Console.WriteLine(notifications); // 1
```

Для отписки от лямбды сохраните делегат в переменной. Новый синтаксически похожий обработчик
не обязан совпадать с тем, который добавили раньше. Именованный метод облегчает симметричную отписку.

## Время жизни и ошибки наблюдателя

Пока издатель доступен, его событие может удерживать делегат, а делегат — объект подписчика.
Если долгоживущий сервис хранит обработчик закрытого окна, окно остаётся достижимым для GC.
Владелец подписки должен отписываться в подходящий момент, например Dispose.
Граф ссылок объясняет утечку надёжнее ожидания, что принудительный GC обязательно её продемонстрирует.

В Counter состояние изменяется до уведомления. Если обработчик бросит исключение, Value уже увеличен.
В L02 Add тоже сначала сохраняет расход, затем поднимает Added. Ошибка наблюдателя не откатывает запись.
Такое поведение нужно документировать; надёжная доставка событий требует других механизмов в будущих главах.

Async-обработчик события часто имеет форму async void. Его нельзя ожидать как Task обычным вызовом события;
исключения после асинхронного продолжения имеют другие пути обработки. До главы 31 используйте здесь
синхронные короткие обработчики и не считайте event гарантией завершения фоновой работы.

## Практика

**14-A.** Напишите метод отбора положительных decimal, принимающий `Func<decimal,bool>`.
Критерий: для −1, 0, 2, 5 предикат >0 даёт 2,5; предикат >=5 даёт только 5.
Алгоритм перебора не меняется при замене условия.

**14-B.** Воспроизведите 3,3,3 через for и исправьте на 0,1,2 локальной копией.
Критерий: объясните, сколько переменных захвачено в обоих вариантах.
Сделайте отдельный вариант со static-лямбдой и явным параметром вместо захвата.

**14-C.** Подпишитесь на Counter, увеличьте его, отпишитесь и увеличьте ещё раз.
Критерий: уведомление одно, значение счётчика два. Добавьте бросающий обработчик:
проверьте, что состояние уже изменилось, а следующий обработчик не был вызван.
Укажите, какие ссылки нужно разорвать при закрытии подписчика.
