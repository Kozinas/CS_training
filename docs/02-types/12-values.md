# 12. Структуры, записи и равенство

**Результат:** вы выбираете семантику значения или идентичности и создаёте устойчивый ключ коллекции.
Нужна глава 11. Запуск: `dotnet run --project examples/TypesAndQueries -- 12`.

## Значение и место хранения

При присваивании struct копируются его поля. При присваивании ссылки на class копируется ссылка.
Это описание семантики, а не правило «struct всегда в стеке»: структура может быть полем объекта,
элементом массива или оказаться упакованной в managed heap.

```csharp
Point first = new(1, 2);
Point second = first;
Console.WriteLine(first == second); // True

public readonly record struct Point(int X, int Y);
```

Readonly struct запрещает обычное изменение полей экземпляра после создания.
Если поле содержит ссылку на List, сам List по-прежнему может меняться.
Большие структуры дороги при многократном копировании; размер и сценарий важнее желания избежать new.

Default структуры существует независимо от проверок её конструктора.
`default(Money)` и элементы `new Money[10]` могут содержать нулевые поля без вызова
пользовательского конструктора. В L02 нулевая сумма — допустимый Money, но расход с нулём запрещён.
Так контракт типа совместим с default, а более строгое правило находится в Expense.

## Records и обычные классы

Обычный class по умолчанию имеет ссылочное равенство; record создаёт реализацию равенства по данным.
`record` без struct означает record class. Record не гарантирует глубокую неизменяемость:
изменяемые поля и свойства допустимы, а вложенные объекты сохраняют собственную семантику равенства.

```csharp
Person first = new("Ann");
Person second = new("Ann");
Console.WriteLine(first == second);                // True
Console.WriteLine(ReferenceEquals(first, second)); // False
Person renamed = first with { Name = "Bob" };
Console.WriteLine(first.Name);                     // Ann

public sealed record Person(string Name);
```

With создаёт поверхностную копию. У записи с List в свойстве исходник и копия могут ссылаться
на один список. Два отдельных списка с одинаковыми элементами сами по себе не становятся равными
из-за включения в record. Если нужен глубокий набор значений, спроектируйте его явно.

Позиционные параметры record создают публичные свойства и Deconstruct.
У обычного `class Worker(string name)` primary constructor делает параметр доступным в теле типа,
но автоматически не объявляет public Name. Это разные соглашения синтаксиса.
Позиционный record struct по умолчанию допускает изменение свойств; readonly record struct — нет.

## Договор Equals и GetHashCode

Если `a.Equals(b)` истинно, хеши должны совпадать. Обратное неверно: коллизии допустимы.
Равенство должно быть рефлексивным, симметричным и транзитивным для обычных значений типа.
Для самостоятельно реализованного value object согласуйте `Equals(object?)`,
`IEquatable<T>.Equals`, GetHashCode и операторы `==`/`!=`.

Не изменяйте поля, участвующие в хеше, после добавления объекта в Dictionary или HashSet:
объект может остаться в контейнере, но перестать находиться ожидаемым способом.
Не сохраняйте GetHashCode в файл как постоянный идентификатор — он не обещает стабильность между процессами.

Идентичность сущности и равенство снимков данных — разные вопросы.
В L02 записи сравниваются по всем данным, а уникальность в хранилище определяется только Id.
Одинаковый Id с другой суммой всё равно является конфликтом добавления.

## Boxing и unboxing

```csharp
int original = 7;
object boxed = original; // boxing: отдельное упакованное значение
original = 9;
Console.WriteLine((int)boxed); // 7
long wide = (int)boxed;        // сначала unboxing int, затем int -> long
```

`(long)boxed` выбросит InvalidCastException: внутри упакован именно int.
Передача структуры через object или интерфейс может вызвать boxing. Generic-коллекция
`List<int>` позволяет хранить числа без упаковки каждого элемента как object.
Оценивать влияние упаковки на скорость будем измерениями в главе 34.

## Enum и кортежи

```csharp
[Flags]
enum Permission { None = 0, Read = 1, Write = 2, Export = 4 }
```

Отдельные флаги выбирают степенями двойки. `Read | Write` объединяет, проверка через `&`
выделяет бит. Атрибут Flags не запрещает неизвестные биты.
Приведение `(Permission)128` возможно; входные значения проверяются отдельно.
Enum.IsDefined подходит для отдельных именованных значений, но не для всех комбинаций Flags.

Кортеж `(int Count, decimal Total)` удобен для локального результата из двух величин.
Он основан на ValueTuple; имена элементов не задают новую несовместимую разновидность типа.
Деконструкция `var (count, total) = summary;` присваивает компоненты локальным переменным.
Для публичной предметной модели отдельный именованный тип обычно лучше выражает правила.

## Практика

**12-A.** Создайте readonly record struct Point и HashSet из (1,2), (1,2), (2,1).
Критерий: Count=2. У двух отдельных record class Person("Ann") проверьте одновременно
равенство данных и несовпадение ссылок.

**12-B.** Реализуйте Money для одной условной валюты: decimal, неотрицательное значение,
не более двух значащих знаков после точки; ноль допустим. Добавьте сложение.
Критерии: default равен Money(0), 1.20+2.30=3.50; −1 и 1.001 отклоняются.
Уточнение: 1.2300m допустимо, поскольку значение точно выражается двумя знаками.

**12-C.** Создайте record с `List<string> Tags` и выполните with. Измените Tags копии.
Критерий: воспроизведено общее изменение; затем устраните его отдельной копией списка.
Объясните, почему для элементов-классов даже этого может быть недостаточно.
