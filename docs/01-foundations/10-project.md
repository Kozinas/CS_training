# 10. Практикум ExpenseLedger CLI

**Результат:** готовая консольная программа читает расходы, проверяет формат и выводит отчёт.
Нужны главы 01–09. Подробный договор — в [лабораторной L01](../../labs/01-expense-ledger/README.md).

## Постановка задачи

Пользователь хранит небольшую выгрузку расходов в UTF-8 файле. Ему нужны число записей,
сумма и суммы по категориям. Формат не должен зависеть от языка Windows.
В ошибочной выгрузке нужно указать номер строки, чтобы её можно было исправить.
При ошибке данных успешный отчёт не выдаётся.

Это первая объединённая работа: она требует почти всех уже изученных приёмов.
Сначала реализуйте её в `work/ExpenseLedger`. Полный пример в `examples/ExpenseLedger`
используйте для сравнения после собственной попытки.

## Разделение ответственности

```text
аргументы → открытие файла → строки → проверка и Expense
                                      ↓
                         список проверенных расходов
                                      ↓
                         итог и группы по категориям
                                      ↓
                            форматированный отчёт
```

У программы четыре границы: аргументы процесса, файловая система, текстовый формат и модель данных.
Каждая требует своего решения. Неверный decimal нельзя превращать в 0: это создаст фиктивный расход.
Нельзя также складывать данные до проверки всех строк и печатать частичный результат как полный.

Разумный первый набор методов: `TryParseLine`, `TryParseAmount`, `ReadAll`, `WriteReport`.
Два первых отвечают за данные, следующие — за I/O. Класс Expense сохраняет инварианты.
Сложные generic-абстракции на этом этапе не нужны.

## Шаги реализации

1. Создайте консольный проект net10.0, включите nullable и убедитесь, что он запускается.
2. Обработайте отсутствие пути и лишние аргументы. Проверьте код завершения.
3. Напишите разбор суммы на отдельных строках. Проверьте границы до чтения файла.
4. Разберите строку на три поля и проверьте дату, категорию и сумму.
5. Создайте тип Expense и запретите недопустимое состояние.
6. Прочитайте файл, сохранив физические номера строк, включая пустые.
7. Посчитайте итог и группы через Dictionary. Отсортируйте ключи явно.
8. Добавьте обработку ошибок чтения, строгую кодировку и раздельные stdout/stderr.
9. Пройдите все сценарии приёмки и напишите короткую инструкцию запуска.

Даты используют новый для вас тип `DateOnly` из BCL: он хранит календарную дату без времени и зоны.
`TryParseExact` с шаблоном `yyyy-MM-dd` проверяет реальную дату, например отклоняет 2026-02-30.
Не пытайтесь проверить календарь только количеством символов и тире.

## Разобранный алгоритм отчёта

Для каждой записи увеличьте общее число и общую сумму. Получите предыдущую сумму категории
через TryGetValue и запишите новую. Категории по договору нечувствительны к регистру;
нормализуйте их к нижнему ASCII-регистру и используйте Ordinal для ключей.

После окончания расчёта создайте список ключей словаря, отсортируйте его и выведите значения
в F2 и InvariantCulture. Сумма для входа из примера — 50.00 независимо от CurrentCulture.
Приведение регистра допустимо здесь потому, что формат категорий ограничен ASCII и результат
должен иметь каноническое написание. Для произвольных пользовательских строк правила шире.

## Проверка решения

Проверьте success, пустой файл, повтор категории с разным регистром, несуществующий файл,
невозможную дату, отрицательную сумму, лишнее поле и неправильную кодировку.
Для каждого случая проверяются три наблюдаемых результата: stdout, stderr и exit code.

Готовый пример запускается так:

```powershell
dotnet run --project examples/ExpenseLedger -- labs/01-expense-ledger/data/valid.txt
python tools/verify.py
```

Проверка собственной реализации с тем же контрактом:

```powershell
dotnet build work/ExpenseLedger -c Release
python tools/verify.py --ledger-dll work/ExpenseLedger/bin/Release/net10.0/ExpenseLedger.dll
```

Скрипт использует временные тестовые файлы и сверяет поведение.
Автоматические проверки помогают найти нарушение контракта, но не доказывают качество всех решений.
Перед сдачей самостоятельно объясните выбор типов, условия ветвлений и область жизни reader.

## Практика

**10-A.** Реализуйте основной сценарий L01. Критерий: точное совпадение отчёта из лабораторной.

**10-B.** Реализуйте весь контракт и пройдите сценарии ошибок.
Критерии: при любом ошибочном файле stdout пуст, причина в stderr, код соответствует категории сбоя.
После ошибки в строке 2 программа не должна печатать итог строки 1.

**10-C.** В собственной ветке добавьте необязательный фильтр месяца `yyyy-MM`.
Сначала отдельно запишите новый контракт аргументов. Полный файл всё равно валидируется,
затем фильтруются записи. Критерии: месяц без записей → пустой отчёт;
ошибочная строка вне выбранного месяца всё равно отклоняется.
Базовые проверки B должны проходить при запуске без фильтра. Готовый пример реализует только A/B.

## Допуск к следующему блоку

Объясните без запуска, что произойдёт с `1,50`, `2026-02-30`, `FOOD`, UTF-16 файлом
и EOF в пустом файле. Покажите в коде единственное место определения допустимого формата суммы.
