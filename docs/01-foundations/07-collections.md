# 07. Массивы и базовые коллекции

**Результат:** вы храните набор значений, выбираете структуру под операцию и учитываете общие ссылки.
Нужна глава [06](06-text-null.md).

## Массив и индекс

Массив хранит фиксированное число элементов одного типа. Индексы начинаются с нуля;
последний — `Length - 1`.

```csharp
int[] values = [10, 20, 30]; // коллекционное выражение, C# 12+
Console.WriteLine(values[0]);  // 10
Console.WriteLine(values[^1]); // 30, первый с конца
int[] firstTwo = values[..2]; // новая копия [10, 20]
```

`new int[3]` создаёт три нуля. `new string[3]` создаёт три null, даже если тип элементов
написан как string и nullable-анализ включён. Заполненность массива — отдельная ответственность.
Индекс за границами приводит к исключению. Для пустого массива обращение к `[^1]` тоже ошибочно.

Прямоугольный массив объявляют `int[,] matrix = new int[2, 3];`.
Ступенчатый `int[][] rows` — массив ссылок на массивы, строки могут иметь разную длину.
Это разные модели: вложенный foreach и размеры нужно выбирать соответственно.

## Копия ссылки и копия данных

```csharp
int[] original = [1, 2];
int[] alias = original;
alias[0] = 9;
Console.WriteLine(original[0]); // 9

int[] copy = original[..];
copy[0] = 7;
Console.WriteLine(original[0]); // 9
```

Присваивание копирует ссылку на тот же массив. Срез массива создаёт новый массив.
Если элементы сами ссылки на изменяемые объекты, копия массива всё ещё содержит ссылки
на те же элементы: это поверхностное копирование. Для span семантика среза будет другой —
представление той же памяти, глава 23.

## Выбор коллекции

| Структура | Для чего | Важные свойства |
| --- | --- | --- |
| `List<T>` | Упорядоченный изменяемый список | Индекс O(1), поиск O(n), добавление в конец обычно O(1) амортизированно |
| `Dictionary<TKey,TValue>` | Поиск значения по ключу | В среднем O(1), уникальные ключи |
| `HashSet<T>` | Уникальные элементы | В среднем O(1) для поиска/добавления |
| `Queue<T>` | Первый пришёл — первый вышел | Enqueue/Dequeue |
| `Stack<T>` | Последний пришёл — первый вышел | Push/Pop |

`T` — параметр типа. `List<decimal>` хранит decimal; детальное устройство обобщений будет позже.
Оценка O(n) означает рост работы пропорционально размеру набора, а не конкретное число миллисекунд.
Хеш-коллекции не гарантируют постоянное время для любого входа; качество хешей и сравнение важны.

```csharp
List<decimal> amounts = [12.50m, 7.50m];
amounts.Add(3m);
decimal total = 0m;
foreach (decimal amount in amounts)
{
    total += amount;
}
Console.WriteLine(total); // числовое значение 23.00
```

`Count` — текущее число элементов списка, `Capacity` — ёмкость внутреннего хранения.
Изменять состав списка при foreach обычно нельзя: перечислитель обнаруживает изменение.
Для удаления используйте отдельный список результатов, RemoveAll или подходящий индексный цикл.

## Группировка без LINQ

```csharp
Dictionary<string, decimal> totals = new(StringComparer.OrdinalIgnoreCase);
string[] categories = ["food", "travel", "FOOD"];
decimal[] amounts = [12.50m, 30m, 7.50m];

for (int i = 0; i < categories.Length; i++)
{
    string category = categories[i];
    totals.TryGetValue(category, out decimal previous);
    totals[category] = previous + amounts[i];
}
Console.WriteLine(totals["food"]);   // числовое значение 20.00
Console.WriteLine(totals["travel"]); // числовое значение 30.00
```

При отсутствующем ключе TryGetValue возвращает false и default для значения.
Для decimal это 0, что здесь удобно. Доступ `totals["missing"]` для чтения выбросит исключение;
для записи индексатор добавляет или обновляет элемент. Add с уже существующим ключом — ошибка.

Не используйте порядок Dictionary как договор отчёта. Если результат должен воспроизводиться,
извлеките ключи в List и вызовите `Sort(StringComparer.Ordinal)`, затем выводите по этому порядку.
Параллельные массивы в примере требуют одинаковых длин; в следующей главе объединим связанные данные в объект.

## Практика

**07-A.** Для массива `[3, 1, 4]` найдите сумму, минимум и максимум без LINQ.
Критерии: 8, 1, 4. Для пустого массива сумма 0, а минимум/максимум явно отсутствуют;
не выдавайте ноль за найденный минимум.

**07-B.** Реализуйте приведённую группировку самостоятельно.
Критерии: food=20.00, travel=30.00; `FOOD` и `food` объединяются; вывод отсортирован.
Добавьте четвёртую запись transport=0.01 и проверьте общую сумму 50.01.

**07-C.** Сделайте очередь из команд `add`, `report`, `quit` и обработайте её до quit.
Сравните результат с теми же командами в Stack. Затем создайте HashSet идентификаторов
`a, b, a`: критерий — два уникальных элемента. Объясните выбор структур словами.
