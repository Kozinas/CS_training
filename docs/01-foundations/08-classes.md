# 08. Классы и инварианты

**Результат:** вы объединяете связанные данные и поддерживаете допустимое состояние объекта.
Нужна глава [07](07-collections.md).

## Тип и экземпляр

Класс описывает данные и действия. Экземпляр — отдельный объект этого класса.
Если категория и сумма лежат в разных массивах, их длины и индексы легко перепутать.
Объект Expense хранит их вместе.

Ниже полный тип для отдельного файла `Expense.cs`:

```csharp
namespace Course;

public sealed class Expense
{
    public string Category { get; }
    public decimal Amount { get; }

    public Expense(string category, decimal amount)
    {
        if (string.IsNullOrWhiteSpace(category))
        {
            throw new ArgumentException("Категория обязательна.", nameof(category));
        }
        if (amount <= 0m)
        {
            throw new ArgumentOutOfRangeException(nameof(amount), "Сумма должна быть положительной.");
        }

        Category = category.Trim();
        Amount = amount;
    }
}
```

`throw` завершает нормальный ход создания объекта исключением; обработка — в главе 09.
`nameof(amount)` получает имя параметра как строку и сохраняет связь при переименовании.
После успешного конструктора всегда есть непустая категория и положительная сумма:
это инвариант объекта. `sealed` запрещает наследование от класса; наследование рассмотрим позже.

В `Program.cs` того же проекта:

```csharp
using Course;

Expense expense = new("food", 12.50m);
Console.WriteLine(expense.Category);
// expense.Amount = -1m; // не компилируется: доступного setter нет
```

Здесь два файла одного проекта, а не две самостоятельные программы.
Запускаемый пример главы находится в проекте Foundations.

## Поле, свойство и доступность

Поле хранит значение непосредственно. Свойство задаёт доступ через get/set.
Авто-свойство позволяет компилятору создать backing field. Публичный set разрешает изменение;
private set оставляет его внутри класса; get без set в этом примере задаётся при создании.

| Модификатор | Доступ |
| --- | --- |
| `public` | Доступен потребителям типа |
| `private` | Только внутри содержащего типа |
| `internal` | Внутри сборки |
| `protected` | В типе и производных типах |
| `protected internal` | В сборке или в производном типе |
| `private protected` | В производном типе в той же сборке |

Тип верхнего уровня без модификатора обычно internal, члены класса — private.
Вложенные типы имеют свои правила области видимости. Папка проекта не задаёт namespace автоматически.

`this` обозначает текущий экземпляр. `static`-поле принадлежит типу, поэтому все экземпляры
наблюдают одно состояние. Такая общая изменяемая переменная усложняет тестирование и конкуренцию;
не превращайте её в универсальное хранилище.

## Неизменяемость и инициализация

`readonly`-поле можно присвоить при объявлении или в соответствующем конструкторе.
Если оно содержит List, запрещено присвоить другой список; добавлять элементы в существующий
список всё ещё можно. Неизменяемость ссылки не равна неизменяемости объекта.

`init` позволяет присваивание в фазе инициализации, а `required` требует указания члена
при создании по правилам компилятора. Например, object initializer выглядит как
`new Options { Title = "Report" }`. Ни init, ни required сами по себе не проверяют,
что строка непустая, а число положительное.

Конструктор в нашем примере связывает проверку и создание. Внешнему коду нельзя предложить
сначала `new Expense()`, затем отдельно «не забудьте вызвать Validate».
Для типов с изменяемым состоянием методы должны сохранять инвариант после каждого действия.

## Общие ссылки

```csharp
List<Expense> first = [new("food", 12.50m)];
List<Expense> second = first;
second.Add(new("travel", 30m));
Console.WriteLine(first.Count); // 2
```

Списки first и second — два имени для одного объекта. Создание нового `List<Expense>(first)`
копирует набор ссылок, но не создаёт новых Expense. В данном примере элементы предоставляют
только чтение, поэтому совместное использование упрощается. Для изменяемого элемента оно требует осторожности.

Композиция означает, что один объект содержит другой и делегирует ему работу.
Для журнала расходов естественнее хранить список Expense внутри Ledger, чем наследовать Ledger от List.
Так можно разрешить только предметные операции и сохранять правила.

## Практика

**08-A.** Создайте Expense в отдельном файле и два разных экземпляра.
Критерий: изменение списка с одним объектом не создаёт автоматически второй объект;
покажите совпадение ссылок через `ReferenceEquals` при присваивании.

**08-B.** Создайте `Product` с непустым Name и Price > 0, только get-свойства.
Критерии: `("Book", 15m)` создаётся; пустое имя, пробелы, 0 и −1 отклоняются конструктором.
Попытка присвоить Price снаружи не компилируется. Проверяйте такой контрпример в отдельной копии.

**08-C.** Создайте `Basket`, который содержит `private List<Product>`, метод Add и метод Total.
Не выдавайте наружу изменяемый список. Критерий: два товара 15m и 7.5m дают 22.5m,
пустая корзина — 0m. Объясните, какое правило проще поддерживать благодаря закрытому списку.
