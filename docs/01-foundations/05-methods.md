# 05. Методы и декомпозиция

**Результат:** вы выделяете проверяемое вычисление из ввода-вывода и объясняете передачу аргументов.
Нужна глава [04](04-control.md).

## Контракт метода

Метод получает параметры, выполняет работу и возвращает результат. Контракт определяет
допустимые входы и обещанный результат. Например, расчёт скидки принимает неотрицательную сумму
и процент от 0 до 100. Пока вызывающая сторона проверяет эти условия через if.

Полный вариант в top-level `Program.cs`:

```csharp
decimal result = CalculateTotal(125.50m, 4, 15m);
Console.WriteLine(result); // числовое значение 426.70

static decimal CalculateTotal(decimal price, int count, decimal discountPercent)
{
    decimal subtotal = price * count;
    decimal discounted = subtotal * (1 - discountPercent / 100m);
    return Math.Round(discounted, 2, MidpointRounding.ToEven);
}
```

В этом контексте объявлена локальная static-функция в сгенерированной точке входа.
В классе похожее объявление является static-методом. `static` означает, что для вызова
не нужен экземпляр класса; static локальная функция также не захватывает окружающие переменные.

Метод с типом результата `void` не возвращает значение. Оператор `return;`
может досрочно завершить его. В методе с результатом все нормально завершающиеся пути
должны вернуть значение.

Выделенное вычисление не читает Console и не пишет файл. Оно легче проверяется:
одинаковые аргументы дают один результат. Вывод остаётся ответственностью вызывающего кода.

## Параметр и аргумент

Параметр — имя в объявлении, аргумент — значение при вызове.
Именованные аргументы делают понятнее несколько одинаково типизированных значений:

```csharp
decimal total = CalculateTotal(price: 100m, count: 2, discountPercent: 10m);
```

Необязательный параметр задаёт значение по умолчанию в объявлении.
Это значение подставляется при компиляции вызывающего кода: изменение default в библиотеке
не обновляет уже скомпилированного клиента автоматически.

Перегрузка — несколько методов с одним именем и разными наборами параметров.
Только возвращаемого типа для различения недостаточно.
Для начальных упражнений предпочитайте разные понятные имена спорным перегрузкам.

`params` принимает переменное число аргументов. Классический пример:

```csharp
static int Sum(params int[] values)
{
    int total = 0;
    foreach (int value in values)
    {
        total = checked(total + value);
    }
    return total;
}
```

`Sum(1, 2, 3)` вернёт 6, `Sum()` — 0. Массивы подробно разбираются в главе 07.
Новые варианты params для коллекций изучаются после обобщений.

## Передача по значению и по ссылке

По умолчанию копируется значение аргумента. Для int это число. Для ссылки на объект
копируется ссылка; два имени могут указывать на один объект. Фраза «все объекты передаются
по ссылке» скрывает важное различие между копированием ссылки и ref-параметром.

```csharp
int number = 10;
Change(number);
Console.WriteLine(number); // 10
Increase(ref number);
Console.WriteLine(number); // 11

static void Change(int value) => value = 99;
static void Increase(ref int value) => value++;
```

`ref` даёт методу доступ к переменной вызывающей стороны. Она должна быть заранее инициализирована.
`out` позволяет методу присвоить результат; он обязан присвоить его на всех нормально завершающихся путях.
`in` предоставляет чтение аргумента по ссылке и не гарантирует отсутствие всех копий или ускорение.
Начинайте с обычных параметров; модификаторы вводите ради понятного контракта.

## Try-паттерн

Ожидаемо неверный текст удобно выражать результатом bool и out-значением:

```csharp
static bool TryReadCount(string text, out int count)
{
    count = 0;
    if (!int.TryParse(text, out int parsed) || parsed < 1 || parsed > 100)
    {
        return false;
    }

    count = parsed;
    return true;
}
```

Вызывающий код сначала проверяет bool. Для `"12"` получит true и 12;
для `"0"`, `"abc"`, `"101"` — false и 0. Парсинг ещё не означает валидацию:
`int.TryParse("0", ...)` успешен, но правило количества запрещает ноль.

## Рекурсия и размер метода

Рекурсивный метод вызывает себя и должен приближаться к базовому случаю.
Для факториала `0! = 1`, а для n > 0 результат равен n × (n−1)!.
Каждый незавершённый вызов требует места в стеке; очень глубокая рекурсия опасна.
Для длинных линейных последовательностей цикл обычно проще.
C# не обещает автоматическое устранение хвостовой рекурсии.

Хорошая граница метода — одна ответственность, которую можно назвать и проверить.
Метод, который спрашивает путь, читает файл, считает скидки и печатает отчёт,
связывает несколько независимых причин изменения.

## Практика

**05-A.** Выделите `CalculateTotal` и вызовите его для трёх случаев:
100×2, скидка 10 → 180; 5×1, скидка 100 → 0; 0×3, скидка 0 → 0.
Критерий: внутри метода нет Console.

**05-B.** Реализуйте `TryReadCount` без копирования. Критерии:
`"1"` и `"100"` успешны, `"0"`, `"101"`, `"-2"`, `"x"` отклонены.
При отказе out-параметр равен 0.

и результатом long. Критерии: 0 → 1, 5 → 120, 20 → 2432902008176640000.
