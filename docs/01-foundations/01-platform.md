# 01. C# и .NET, рабочая среда

**Результат:** вы создаёте проект, собираете и запускаете его из терминала и понимаете,
какой инструмент участвует на каждом шаге. Предыдущие знания: [маршрут](../00-start.md).

## Язык, платформа и библиотека

C# задаёт правила исходного кода: какие значения существуют, как вызвать метод и как описать тип.
Компилятор Roslyn проверяет код и обычно создаёт сборку с промежуточным кодом IL и метаданными.
Среда CLR загружает сборку, управляет выполнением, исключениями и памятью. JIT обычно переводит
IL нужных методов в машинный код во время работы. Позже мы разберём предварительную компиляцию,
в том числе Native AOT: схема исполнения не всегда ограничивается JIT.

.NET включает среду выполнения и библиотеки. Например, `if` — конструкция языка,
а `Console.WriteLine` — метод библиотеки. ASP.NET Core, EF Core и WPF решают прикладные задачи;
они не являются частью синтаксиса C#.

```text
Program.cs + .csproj
        ↓ dotnet build / Roslyn
сборка .dll с IL и метаданными
        ↓ dotnet run / CLR и JIT
выполняющаяся программа
```

SDK содержит средства разработки и сборки. Runtime нужен для выполнения уже собранного
framework-dependent приложения. Наличие runtime не гарантирует, что можно собрать проект.
Современный .NET работает на нескольких ОС; .NET Framework — отдельная Windows-платформа,
важная при сопровождении старых систем.

## Среда курса

Используем .NET 10 LTS и C# 14. Соответствие подтверждено в
[описании C# 14](https://learn.microsoft.com/en-us/dotnet/csharp/whats-new/csharp-14);
срок поддержки .NET 10 до 14 ноября 2028 указан в
[политике .NET](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).
Дата выбора среды: 22 октября 2026. Preview-функции для упражнений не нужны.

Проверьте установку:

```powershell
dotnet --info
dotnet --list-sdks
```

Нужен SDK `10.0.x`. Если его нет, установите [.NET 10 SDK](https://dotnet.microsoft.com/en-us/download/dotnet/10.0).
Редактор выбирайте по удобству: Visual Studio с поддержкой .NET 10, Rider или VS Code с C#-инструментами.
Обязательный минимум курса воспроизводится CLI и не зависит от конкретной IDE.

## Первая программа

Создайте новый проект в папке собственных решений:

```powershell
dotnet new console -n HelloCourse -o work/HelloCourse --framework net10.0
dotnet build work/HelloCourse
dotnet run --project work/HelloCourse
```

В `Program.cs` замените содержимое:

```csharp
Console.WriteLine("Начинаю изучать C#");
Console.WriteLine(7 + 5);
```

Получатся две строки: сообщение и `12`. Одна инструкция заканчивается `;`.
Вызов метода указывает действие, аргумент в скобках — данные для него.
Кавычки обозначают строковый литерал; без кавычек `7 + 5` вычисляется как сумма.

Проект содержит настройки, например:

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
```

`TargetFramework` (TFM) выбирает платформу и доступные API. `Nullable` включает анализ возможного
`null`. `ImplicitUsings` подключает распространённые пространства имён: поэтому в первой строке
не пришлось писать `System.Console`. `LangVersion` отдельно выбирает версию синтаксиса.
Менять её на `preview` или `latest` для выполнения базовых заданий не требуется.

## Что делают команды

| Команда | Назначение |
| --- | --- |
| `dotnet restore` | Разрешить зависимости проекта и подготовить assets |
| `dotnet build` | Проверить и скомпилировать |
| `dotnet run` | Собрать при необходимости и запустить |
| `dotnet test` | Выполнить тестовые проекты через настроенный test runner |
| `dotnet publish` | Подготовить файлы для поставки приложения |

Обычно `build` и `run` вызывают restore автоматически. Пакет — внешняя зависимость, namespace —
группа имён, а assembly — единица сборки и загрузки. Это разные понятия.
О поведении создания проектов см. [dotnet new](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-new).

Solution объединяет несколько проектов для работы в IDE и CLI. Для курса используется
`examples/CSharpCourse.slnx`. В `bin` находятся результаты сборки, в `obj` — промежуточные данные.
Эти каталоги не редактируют как исходники.

## Запуск готового примера

```powershell
dotnet run --project examples/Foundations -- 01
```

`--` отделяет параметры приложения от параметров `dotnet run`.
Проверьте, что получены `Hello, C#!` и `12`. Затем запустите пример из IDE с breakpoint
на выводе суммы и выполните одну инструкцию за раз.

## Практика

**01-A.** Создайте `HelloCourse`, выведите своё имя и результат `17 * 3`.
Критерий: две отдельные строки, вторая — `51`; сборка без ошибок.

**01-B.** Создайте вторую программу `Distance`: скорость `72` км/ч, время `3` часа.
Критерий: строка `Distance: 216 km`. Отдельно запустите build, затем run с `--no-build`.
Объясните, что произойдёт, если изменить исходник и сразу повторить `--no-build`.

**01-C.** Подготовьте публикацию `Distance` командой
`dotnet publish work/Distance -c Release -o work/publish-distance`.
Запустите `dotnet work/publish-distance/Distance.dll`.
Критерий: тот же результат, вы можете указать папку проекта и папку поставки.
Это framework-dependent публикация: на другой машине потребуется подходящий runtime.
