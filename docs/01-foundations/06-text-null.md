# 06. Строки, null и культура

**Результат:** вы задаёте однозначный формат данных и обрабатываете отсутствие значения.
Нужна глава [05](05-methods.md).

## Строка и символ

`string` — неизменяемая последовательность кодовых единиц UTF-16.
Методы `Trim`, `Replace` и `ToUpperInvariant` возвращают строку; исходный объект не меняется.

```csharp
string original = " food ";
string cleaned = original.Trim();
Console.WriteLine(original.Length); // 6
Console.WriteLine(cleaned.Length);  // 4
Console.WriteLine("\U0001F600".Length); // 2 кодовые единицы UTF-16, emoji
```

Один `char` не всегда соответствует одному видимому символу. `Rune` представляет
Unicode scalar value, а составной видимый символ может включать несколько таких значений.
Обрезание пользовательского текста по индексам char способно разрезать суррогатную пару.
Для текстовых элементов существует `StringInfo`; практическая работа с Unicode будет в главе 26.

## Запись и построение строк

```csharp
string escaped = "first\nsecond";       // перевод строки
string path = @"C:\data\expenses.txt"; // обратные слэши буквально
string category = "food";
decimal amount = 12.50m;
string message = $"{category}: {amount:F2}";
string json = """{"category":"food","amount":12.50}""";
Console.WriteLine(message);
```

В строке с `$` выражения внутри фигурных скобок вычисляются. `:F2` задаёт два знака
после десятичного разделителя, но не закрепляет культуру. Raw literal использует тройные
кавычки; для многострочных raw strings важен отступ перед закрывающими кавычками.

Для нескольких фрагментов достаточно интерполяции. При накоплении большого текста
в цикле `StringBuilder` позволяет уменьшить создание промежуточных строк.
Не заменяйте все строки на StringBuilder без измерения и понятной причины.

## Правила сравнения

Для команды, ключа протокола или категории из формата данных удобно явно выбрать:

```csharp
bool same = string.Equals("FOOD", "food", StringComparison.OrdinalIgnoreCase);
Console.WriteLine(same); // True
```

`Ordinal` сравнивает кодовые единицы, `OrdinalIgnoreCase` дополнительно игнорирует регистр
по соответствующим правилам .NET. Пользовательская алфавитная сортировка требует культурных правил.
Сравнение строк нельзя универсально заменить вызовами `ToLower()`: это создаёт строки и
скрывает выбор культуры. Подробнее: [сравнение строк](https://learn.microsoft.com/en-us/dotnet/standard/base-types/best-practices-strings).

## Число и его текстовое представление

У числа нет «запятой внутри». Разделитель относится к разбору и форматированию текста.
Для машинного формата курса используем точку, запрет разделителей тысяч и явный InvariantCulture.

```csharp
using System.Globalization;

bool ok = decimal.TryParse(
    "12.50",
    NumberStyles.AllowDecimalPoint,
    CultureInfo.InvariantCulture,
    out decimal amount);

Console.WriteLine(ok); // True
Console.WriteLine(amount.ToString("F2", CultureInfo.InvariantCulture)); // 12.50
```

Выбранные стили не разрешают знак, пробелы, экспоненту или разделители тысяч.
Разрешённые формы определяются контрактом: `TryParse` не гарантирует ровно два знака после точки.
Например, для строгой суммы в лабораторной мы отдельно проверим цифры и дробную часть.

В интерфейсе для человека можно выбрать его культуру и объяснить допустимый ввод.
Нельзя незаметно использовать системную культуру для постоянного файла: перенос программы на другую
машину тогда меняет смысл данных.

## Отсутствие значения

`int?` — `Nullable<int>`: число либо отсутствие числа.
`string?` — nullable-аннотация ссылочного типа для анализа компилятором.
Она не создаёт новый CLR-тип строки и не вставляет автоматическую проверку во время выполнения.
Подробнее: [nullable reference types](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/null-safety/nullable-reference-types).

```csharp
string? input = Console.ReadLine();
if (input is null)
{
    Console.WriteLine("Конец ввода");
    return;
}

string name = input.Trim();
Console.WriteLine(name.Length); // здесь input уже проверен
```

`null`, `""` и `"   "` — разные состояния. `string.IsNullOrWhiteSpace` объединяет их
для задач, где ни одно не считается заполненным именем.

```csharp
string? comment = null;
int length = comment?.Length ?? 0;
comment ??= "Без комментария";
Console.WriteLine(length);  // 0
Console.WriteLine(comment); // Без комментария
```

`?.` прекращает доступ, если слева null. `??` выбирает запасное значение при null,
а `??=` присваивает его только при null. Оператор `!` после выражения лишь подавляет
предупреждение компилятора. `comment!.Length` всё равно упадёт, если comment действительно null.
Не устраняйте предупреждения массовым добавлением `!`.

## Практика

**06-A.** Для `null`, пустой строки, трёх пробелов и `" C# "` определите, допустимо ли имя.
Критерий: первые три отклонены, четвёртое преобразовано в `"C#"`.
Различите завершение ввода и введённое пустое имя.

**06-B.** Напишите `TryReadAmount`: допустимы неотрицательные десятичные числа с точкой,
без знака, пробелов и разделителя тысяч. Используйте явный NumberStyles.
Критерии: `12.50` → 12.5m, `0` → 0m; `12,50`, `1,000`, `-1`, `x` — отказ.
Вывод успешных сумм — F2 и InvariantCulture.

**06-C.** Уточните контракт B: от 1 до 999999.99 включительно, целая часть обязательна,
после точки ровно одна или две цифры; форма без точки разрешена.
Критерии: `1`, `1.5`, `1.50` успешны; `.5`, `1.`, `1.234`, `1000000` отклонены.
Повторите проверки при CurrentCulture `ru-RU` и `en-US`: результат должен совпасть.
