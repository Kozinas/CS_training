# 02. Синтаксис и диагностика

**Результат:** вы читаете короткую программу, находите область видимости переменной и
различаете ошибку компиляции, исключение и неверный результат. Нужна глава [01](01-platform.md).

## Из чего состоит код

Идентификатор — имя: `total`, `Calculate`, `Expense`. Регистр существенен:
`total` и `Total` различаются. Ключевые слова, например `int` и `return`, имеют заданный смысл.
Встречающееся в чужом коде `@class` — идентификатор с экранированным ключевым словом.
Для собственных имён выбирайте понятные слова: `expenseCount` точнее, чем `x1`.

Литерал задаёт значение прямо в коде: `42`, `"food"`, `true`.
Выражение вычисляет значение: `price * count`. Инструкция выполняет действие:
`Console.WriteLine(total);`. Блок в фигурных скобках объединяет инструкции.

```csharp
int price = 25;
int count = 4;
int total = price * count;
Console.WriteLine(total); // 100
```

`=` присваивает значение, а `==` сравнивает. Комментарии `//` идут до конца строки;
`/* ... */` могут занимать несколько строк. Поясняйте в комментариях причину решения:
пересказ `count++` словами «увеличить count» редко помогает.

## Переменные и область видимости

Объявление связывает имя с типом. До чтения локальной переменной компилятор должен доказать,
что ей присвоено значение. Поля и элементы массивов имеют значения по умолчанию, но это
не разрешает читать неинициализированную локальную переменную.

```csharp
int total = 10;
{
    int bonus = 2;
    total += bonus;
}
Console.WriteLine(total); // 12
// Console.WriteLine(bonus); // ошибка: bonus вне области видимости
```

Область видимости определяет, где доступно имя; время жизни — как долго существует значение
или объект. Эти понятия связаны, но не совпадают. В дальнейшем замыкание может удерживать
объект после выхода из блока.

## Точка входа

В новых консольных шаблонах используется top-level код. Компилятор создаёт точку входа.
В проекте может быть только один файл с такими инструкциями; они идут перед объявлениями
типов в этом файле. Вторую программу нельзя просто дописать в другой файл того же проекта.

Традиционная форма того же начала программы:

```csharp
namespace Course;

internal class Program
{
    private static void Main(string[] args)
    {
        Console.WriteLine("Hello");
    }
}
```

Это альтернативный полный `Program.cs`, а не дополнение к top-level инструкциям.
`namespace` группирует имена, `class` объявляет тип, `Main` — метод точки входа.
`args` содержит аргументы командной строки. Значение `static` разберём в главах 05 и 08.
`using System;` позволяет писать `Console` вместо `System.Console`.

## Три вида дефектов

| Вид | Пример | Как искать |
| --- | --- | --- |
| Ошибка компиляции | Неизвестное имя, отсутствует `;` | Сначала первая содержательная диагностика build |
| Ошибка выполнения | Обращение за границы массива | Тип исключения, сообщение и стек вызовов |
| Логическая ошибка | Вместо скидки добавили наценку | Проверка на заранее рассчитанных данных |

Например, `int total = "42";` не компилируется: строку нельзя неявно присвоить целому.
Вычисление `10 / divisor` при `int divisor = 0` выбросит исключение во время выполнения.
А `double average = 5 / 2;` выполнится и даст `2`: деление сначала было целочисленным.
Исправление — `5.0 / 2`, а не смена текста вывода.

## Работа отладчиком

Поставьте breakpoint перед вычислением `total`. Запустите отладку. В Locals или Watch
посмотрите `price` и `count`, затем выполните Step Over. Проверьте новое значение `total`.
Step Into входит в вызываемый метод, Step Out завершает текущий. Call Stack показывает путь вызовов.

Запись ошибки должна содержать: входные данные, ожидаемый результат, фактический результат,
место расхождения и причину. «Не работает» не даёт другому человеку воспроизводимого сценария.
Если несколько ошибок возникают после одной пропущенной скобки, сначала исправьте её и пересоберите.

## Практика

**02-A.** Запустите `dotnet run --project examples/Foundations -- 02`.
До запуска вычислите значения из исходника. Критерий: результат `total=100`.

**02-B.** В своей копии по очереди внесите три дефекта: переименуйте `price` только в объявлении;
поделите на переменную со значением ноль; замените `*` на `+`.
Критерий: для каждого дефекта записаны категория, средство обнаружения и исправление.
Не оставляйте намеренно сломанный код в проекте с другими упражнениями.

**02-C.** Поставьте условный breakpoint перед выводом: `total > 90`.
Для `price=25, count=4` он должен сработать, для `price=10, count=4` — нет.
Критерий: объясните состояние переменных в каждой точке, не добавляя диагностический вывод.
