# Подсказки и разбор контрольных вопросов

Здесь намеренно даны направления решения и объяснения, а не готовые программы для всех задач.
Открывайте соответствующий пункт после самостоятельной попытки. Полные учебные примеры находятся
в [examples](../../examples/README.md), эталон L01 — в [ExpenseLedger](../../examples/ExpenseLedger/Program.cs).

## Главы 01 и 02

01-B: `--no-build` запускает уже собранный результат. Изменённый исходник сам не становится новой сборкой.
01-C: DLL находится в publish-каталоге и запускается подходящим runtime; файл исходника для этого не нужен.

02-B: неизвестное имя обнаруживает компилятор; целочисленное деление на ноль при переменной-делителе —
среда выполнения; замена умножения сложением может быть полностью допустимым кодом.
02-C: условие breakpoint проверяется в точке остановки, где total уже должен быть вычислен.

SDK включает инструменты сборки, runtime исполняет код. Namespace не устанавливает пакет.
Область видимости локального bonus заканчивается вместе с блоком. Диагностика nullable —
не замена проверке внешних данных.

## Глава 03

03-A: `7 / 3` даёт int 2; `7 / 3m` даёт decimal с конечным приближением к 2⅓;
`-7 % 3` равно −1; cast 2.9 к int даёт 2.
03-B: 125.50 × 4 = 502.00; после скидки остаётся 85%, результат 426.70.
03-C: сначала приведите один множитель к long. Присваивание готового переполненного int в long
не восстанавливает потерянное значение. checked должен охватывать именно умножение.

`var` выбирает один статический тип при компиляции. Decimal тоже не является бесконечно точной дробью.
Правило округления принадлежит предметной задаче; его нельзя заменять произвольным приведением.

## Глава 04

04-A: проверьте отрицательное n до цикла. При n=0 цикл от 1 до n не выполняется.
04-B: количество увеличивается только после успешного TryParse.
04-C: храните число последовательных ошибок; сбрасывайте после принятого значения.
Выход через break заканчивает ближайший цикл, через return — весь метод.
EOF приходит как null, Enter без текста — пустая строка.

## Глава 05

05-A: метод должен возвращать число; форматирование делается отдельно.
05-B: заранее присвойте out-параметру 0. Это упрощает все пути отказа.
05-C: рекурсия имеет базовый случай n=0. Невалидный вход отклоняйте до первого рекурсивного вызова.
20! помещается в long, 21! — нет. Цикл не создаёт цепочку рекурсивных вызовов.

Обычный параметр копирует своё значение. Если значение — ссылка, копируется ссылка на общий объект.
Ref позволяет менять переменную вызывающего кода, а out обязан получить значение от метода.

## Глава 06

06-A: сначала различите null и обычную строку, затем проверьте IsNullOrWhiteSpace.
06-B: NumberStyles.AllowDecimalPoint совместно с InvariantCulture не разрешает запятую или знак.
06-C: проверка диапазона и количества цифр выполняется дополнительно к TryParse;
проверяйте ASCII-цифры явно, если таков договор формата.

Для контрольных вопросов: Length считает кодовые единицы UTF-16; `!` меняет анализ компилятора,
но не объект во время выполнения. Ordinal определяет сравнение текста, CultureInfo —
в том числе форматирование чисел. Эти инструменты решают разные задачи.

## Глава 07

07-A: минимум можно инициализировать первым элементом только после проверки непустого массива.
Либо используйте int? и явно представьте отсутствие результата.
07-B: comparer задаётся при создании Dictionary. Числовой итог 50.01 не зависит от порядка перечисления.
07-C: Queue вернёт add, report, quit; Stack начнёт с quit, и обработчик может сразу закончиться.

Срез массива создаёт новый контейнер. Если элементы — ссылки, сами объекты остаются общими.
Словарь обеспечивает поиск по ключу; требуемый порядок отчёта задавайте сортировкой.

## Глава 08

08-A: `Expense second = first;` копирует ссылку. `new Expense(...)` создаёт новый экземпляр.
08-B: get-only свойства и проверка конструктора не позволяют последующим присваиванием нарушить правило.
08-C: Basket содержит список и выдаёт только нужные операции. Внешний код не должен иметь возможность
добавить недопустимый элемент в обход этих операций.

Required требует инициализации по правилам компилятора, но не обещает непустую строку.
Readonly не делает изменяемый объект глубоко неизменяемым.

## Глава 09

09-B: проверяйте число аргументов до открытия файла. Печатайте результат после завершения чтения.
09-C: `new UTF8Encoding(false, true)` включает исключение при неверных последовательностях байтов.
Включение автоматического определения BOM может принять UTF-16; для строгого UTF-8 его отключают.

Using вызывает Dispose при обычном выходе и раскручивании исключения. Throw без аргумента
сохраняет исходную цепочку диагностики. Между Exists и открытием файловая система может измениться.
Ленивая последовательность способна выбросить исключение при MoveNext внутри foreach.

## Глава 10 и L01

Сначала зафиксируйте формат и тестовые строки. Разбор суммы должен иметь один источник правил.
Дата проверяется календарным типом, а не только разделением строки на части.
Полностью прочитанный корректный набор отделяется от вывода — тогда ошибка строки 2 не выдаст отчёт строки 1.

Для 10-C сначала валидируйте весь вход, потом отбирайте месяц. Иначе фильтр случайно скрывает
ошибочные записи и нарушает контракт. Не меняйте денежный расчёт при добавлении фильтра.

Эталонное решение — один из возможных вариантов. После сравнения закройте его и повторно
реализуйте самый трудный метод по собственным тестам.

## Глава 11

11-A: new выбирается по статическому типу; virtual/override связывает вызов с фактическим объектом.
11-B: храните строки в отдельном списке тестового writer и сравните их с ожидаемым набором.
11-C: потребитель чтения должен зависеть только от возможностей чтения.
Если объект обещает возможность записи через общий контракт, постоянный отказ в потомке требует пересмотра модели.

## Глава 12

12-A: record генерирует равенство данных; ReferenceEquals по-прежнему проверяет идентичность ссылок.
12-B: проверьте значение через decimal.Round(amount, 2) == amount, не число знаков в текстовом представлении.
Нулевой default Money должен быть допустим. Ограничение положительности расхода проверяйте в Expense.
12-C: with копирует ссылки на вложенные объекты. Новый List копирует контейнер, но не изменяемые элементы-классы.

Равные объекты обязаны иметь равные хеши, но одинаковый хеш не доказывает равенство.
Уникальность расхода определяется Id, даже когда record сравнивает все данные.

## Глава 13

13-A: `IComparable<T>` обещает CompareTo; для отдельного правила сравнения можно передавать `IComparer<T>`.
13-B: Success(0) нельзя путать с ошибкой. Закрытый конструктор и фабрики ограничивают комбинации состояния.
13-C: producer string безопасен там, где нужен producer object; consumer object — там, где нужен consumer string.
Для `List<string>` запись произвольного object была бы небезопасной, поэтому такого преобразования нет.

## Глава 14

14-A: условие меняется делегатом, а цикл остаётся одним и тем же.
14-B: цикл for захватывает одну переменную i; локальная captured в теле создаёт отдельную переменную на итерацию.
14-C: сохраните экземпляр делегата, чтобы отписаться. Удаление переменной клиента не убирает
ссылку из события долгоживущего издателя. Исключение подписчика не отменяет уже выполненное изменение.

## Глава 15

15-A: finally итератора выполняется при Dispose перечислителя, в том числе через break в foreach.
15-B: вынесите проверку в обычный внешний метод, возвращающий локальный итератор.
15-C: создайте счётчик снаружи генератора. После материализации повторно обходится новый контейнер,
а не первоначальное вычисление. Отдельно проверьте освобождение ресурса, если перебор прерван.

## Глава 16

16-A: Where отбирает чётные, Select умножает, OrderBy задаёт порядок результата.
16-B: GroupBy сохраняет все расходы внутри категории; DistinctBy(category) потерял бы часть сумм.
16-C: ToArray фиксирует набор ссылок/значений на момент перечисления, но не делает глубокую копию элементов.
Any и второй foreach могут запускать два обхода. Нельзя помещать обязательные побочные действия
в селектор и рассчитывать, что любой терминальный метод его вызовет.

## Глава 17

17-A: int-pattern не совпадает с long, даже если число помещается в int.
17-B: list pattern проверяет форму массива, а TryParseExact — смысл строки месяца.
17-C: extension вызывается как статический метод; private-члены Money ему недоступны.
Extension property IsZero работает на C# 14. Для более старого компилятора нужен обычный метод.

## Глава 18 и L02

Snapshot должен копировать контейнер и не выдавать его для изменения. Один IReadOnlyList
над внутренним List не создаёт снимок и не мешает попытке приведения к изменяемому интерфейсу.
В образце используется Array.AsReadOnly над новым массивом неизменяемых Expense.

Неправильный месяц проверяйте до запроса к хранилищу: пустой вход не должен скрывать ошибку аргументов.
Ожидаемый дубликат возвращайте через Result. Ошибка подписчика распространяется после записи;
следующая попытка того же Id должна вернуть duplicate_id. Для 18-C нормализуйте фильтр один раз,
до сравнения с уже нормализованной моделью.

## Глава 19

19-A: начните с typeof выбранного типа, затем Assembly, ManifestModule и EntryPoint.
Имя namespace принадлежит типу, а не каталогу DLL.
19-B: IL работает с вычислительным стеком; JIT может заменить умножение на эквивалентную
инструкцию и использовать регистры. Не требуйте буквального совпадения с исходной записью.
19-C: проверяйте AssemblyName клиента. InternalsVisibleTo не ограничивается одним методом;
не добавляйте его, если достаточно публичного контракта.

Явный статический конструктор даёт однократную инициализацию, но не повторные попытки после сбоя.
Native AOT меняет доступность IL и динамического кода: GetMethodBody не универсальный инспектор.

## Глава 20

20-A: using должен охватывать весь период подписки. Проверяйте количество обработчиков после
нормального выхода и исключения, а не только значение Count внутри блока.
20-B: храните запрошенную длину отдельно от массива. Тестовый пул должен считать Return;
проверка повторного Dispose выявит двойной возврат даже без реального ArrayPool.
20-C: корень удерживает publisher, publisher — делегат, делегат — подписчика.
Finalizer не спасает достижимый подписчик. Снимите подписку там, где заканчивается владение.

ReadOnlySpan не продлевает аренду и не запрещает владельцу изменить массив.
Dispose меняет договор использования ресурса; GC освобождает недостижимую управляемую память.

## Глава 21

21-A: используйте GetProperties и GetCustomAttribute, а не поиск слова NonBlank в исходнике.
21-B: сначала проверяйте форму схемы, потом значения. Ordinal-сортировка имён отделяет
договор результата от неопределённого порядка отражённых членов.
21-C: прямой валидатор знает свойства на этапе компиляции. Генератор может создавать
аналогичные прямые обращения автоматически; работа генератора и работа приложения — разные этапы.

Для AOT нужна публикация и запуск результата, а не только отсутствие ошибок обычного build.
TargetInvocationException у getter не означает, что ошибка произошла в проверке пробелов.
CallerArgumentExpression подставляется компилятором и может быть переопределён вызывающим кодом.

## Глава 22

22-A: сравнивайте значение Title после Emit и загрузки сборки. Экранированная запись исходника
и значение строки выглядят по-разному, но должны представлять одни данные.
22-B: чтение свойства представлено IPropertyReferenceOperation. Проверяйте символ владельца
свойства, учитывайте namespace и отсутствие диагностики для чужого Console.
22-C: сначала разберите дополнительный файл в простую модель (title, edition), затем генерируйте.
Генератор обязан объяснить ошибку ввода и не выдавать полусобранный класс.

Partial-части принадлежат одной компиляции. Analyzer диагностирует существующие операции,
generator добавляет исходник. Инкрементальность зависит от входов и равенства промежуточных моделей.

## Глава 23

23-A: readonly ограничивает действия через конкретную ссылку, но не других владельцев.
23-B: проверьте ASCII-цифры и NumberStyles.None с InvariantCulture; сумму вычисляйте в long.
Второй разделитель останется в правом срезе и должен сделать поле недопустимым.
23-C: оборачивайте аренду в try/finally либо владельца using, ограничивайте длину запроса.
Сначала докажите одинаковый результат на обычных и ошибочных данных, потом измеряйте выделения.

Ref return допустим для элемента живущего у вызывающего кода массива, но не локального stackalloc.
Fixed сохраняет адрес на время блока, однако указатель сам не проверяет индекс.
Показатель выделений текущего потока не является временем выполнения или общим расходом памяти.

## Глава 24

24-A: запускайте dotnet --version из разных каталогов и учитывайте поиск global.json вверх по дереву.
24-B: в setter вычислите и проверьте новое значение до присваивания; при исключении старое останется.
Сравните также начальное значение, чтобы миграция не изменила поведение объекта до первого set.
24-C: обновляйте по одному аспекту. Record меняет равенство, LINQ может менять момент выполнения,
nullable-аннотации уточняют статический договор, но не заменяют проверки входа.

В примере null-conditional assignment пропускает правую часть полностью.
Instance operator += у Counter изменяет объект, видимый через alias; это существенная семантика.
Новый синтаксис считается освоенным, когда вы можете назвать сохраняемый контракт и проверить его.

## Глава 25

25-A: используйте tuple из приоритета и последовательного номера; не полагайтесь на FIFO
встроенной PriorityQueue при равных приоритетах.
25-B: задайте OrdinalIgnoreCase при построении индекса и снимка. AsReadOnly над исходным
изменяемым контейнером не создаёт независимой версии.
25-C: словарь отвечает за Id, очередь — за выбор следующего. При ленивой отмене извлечение
пропускает неактивные записи; не забывайте о накоплении таких записей и политике очистки.

BinarySearch требует того же правила порядка, что сортировка; позиция вставки равна ~result.
GetOrAdd не гарантирует единственный вызов фабрики, поэтому фабрика должна допускать повтор.

## Глава 26

26-A: EnumerateRunes считает scalar values, StringInfo — текстовые элементы; char — UTF-16 единицу.
Используйте escape-записи, чтобы редактор не нормализовал исходный текст незаметно.
26-B: задайте Unspecified для местного показания и передайте TrainingZone явно.
IsInvalidTime и IsAmbiguousTime проверяются до вычисления offset.
26-C: подставьте FixedClock, проверьте now == deadline отдельно от now < deadline.
Для языка ресурсов нужен CurrentUICulture, для машинного формата — InvariantCulture.

DateTime.SpecifyKind меняет описание значения, но не переводит время.
Нормализация Unicode не превращает все похожие буквы разных алфавитов в один символ.

## Глава 27

27-A: CSV quoting и XML escaping относятся к синтаксису формата; проверьте фактическую строку
после разбора. Количество строк файла не равно количеству CSV-записей.
27-B: сначала проверьте envelope, затем каждую RawExpense. Numeric JSON token и строка
с неверной денежной точностью находятся на разных уровнях договора L03.
27-C: временный файл должен быть в том же каталоге, а рабочий файл нельзя удалять заранее.
Для отмены передайте уже отменённый token и сравните старые байты.

ReadAsync может вернуть короткий блок; продолжайте до нуля. Source generation создаёт
метаданные сериализатора, но не проверяет предметные инварианты конструктора за вас.

## Глава 28

28-A: Content-Length может отсутствовать. Ограничивайте сумму реально прочитанных байтов,
а response освобождайте даже при раннем отказе по заголовкам.
28-B: настройте один retry-handler и счётчик на сервере. 503→200 даёт два запроса,
постоянный 404 — один. JSON-проверка происходит после транспортного pipeline.
28-C: сервер сначала отправляет заголовки, затем задерживает тело. Это выявляет ошибку,
когда timeout покрывает только получение response. Для caller cancellation проверяйте token вызывающего кода.

Не заменяйте тест сервера обращением к публичному сайту: его задержки и ошибки не управляются тестом.
Отмена не является rollback уже совершённой записи.

## Глава 29

29-A: сравнивайте ReferenceEquals внутри одного scope и между scope. Singleton принадлежит
контейнеру, а не обязательно всему процессу при наличии нескольких контейнеров.
29-B: appsettings лежит рядом с собранной программой. Переменная с префиксом CS_IMPORT_
подключается позже базовых источников и переопределяет ключ Import:MaxBytes.
29-C: IHostedService обычно живёт всё время host. Внедрите IServiceScopeFactory,
создавайте scope на операцию, передавайте token остановки вниз и ожидайте завершения работы.

Не разрешайте scoped-сервис из root provider и не внедряйте его в singleton напрямую.
Structured logging сохраняет значения полями, а scope добавляет общий контекст batch.

## Глава 30 и L03

30-A: третий объект после нормализации совпадает с первым; шестой конфликтует по сумме.
После первого запуска первые три становятся duplicates, ошибочные записи снова дают ошибки.

51-C: импорт JS выполняется после появления DOM. Освободите module/reference, предусмотрите разрыв circuit.
Browser-тест должен реально нажать кнопку и дождаться изменённой таблицы, а не только получить HTTP 200.

Scoped в Server может жить весь circuit. Static SSR не исполняет интерактивный onclick. bUnit проверяет
компонент и события; сеть браузера, JS, CSS и reconnect требуют отдельных проверок.

## Глава 52

52-A: локальный insert, серверный commit, потерянный локальный ack, повтор прежнего снимка.
Новая квитанция не нужна, если сервер уже сохранил результат под тем же ключом.
52-B: 409 — состояние для разбора. Исправление не меняет байты старого Pending; новая операция получает
новый BatchId. Решение об удалении/замене старого пакета должно быть явно подтверждено в интерфейсе.
52-C: начните с установки шаблонного приложения на устройство; затем переносите проверенное ядро.
При выходе дождитесь остановки синхронизации. Устройство проверяется с отключённой сетью и после остановки процесса.

Connectivity не доказывает достижимость API. Закрытие страницы не доказывает commit, а успешный HTTP
не доказывает локальное удаление Pending. Account key разделяет данные, но не является аутентификацией.

## Глава 53

53-A: после переполнения Id второго pickup должен оставаться доступным. На отказе событие Changed не вызывается.
53-B: создайте проверенный кандидат инвентаря, затем замените состояние целиком. Не меняйте живые слоты
внутри цикла чтения непроверенного save. Возвращайте независимый snapshot.
53-C: назначайте Id объектам уровня и сохраняйте его смысл между входами. Подписка/отписка должны быть
симметричны. Профиль в редакторе не заменяет профиль сборки на целевой платформе.

Языковая версия и набор API — разные оси совместимости. Delta time исправляет скорость простого движения,
но не гарантирует детерминизм физики. Task может пережить владельца; нужны отмена и проверка lifetime.

## Глава 54

54-A: у [500,500] среднее 500 и выборочное отклонение 0. Для одного наблюдения деление на n−1 недопустимо.
54-B: обновляйте count, mean и сумму квадратов отклонений через разность с предыдущим средним;
проверяйте большие близкие значения, пустой поток и повреждённую последнюю строку. Деньги суммируйте отдельно.
54-C: простой baseline может предсказывать наиболее частую категорию; сравните его с моделью на независимых
данных. Для ONNX фиксируйте форму/порядок признаков и используйте известный ответ, а не только успешный Run.

Порядок сложения double влияет на округление; допуск следует из задачи. Exact money total не заменяется
приблизительным SIMD-итогом. Разбиение по времени исключает использование будущего при оценке прошлого.

## Глава 55

55-A: сравнивайте с известным числом записанных байт, включая нулевой файл. Коду Win32 2 соответствует
ERROR_FILE_NOT_FOUND, а CLI имеет собственный exit code 3. Это разные пространства ошибок.
55-B: событие хоста удерживает delegate, который удерживает объект/тип плагина. Сохраните handler,
чтобы снять именно эту подписку; вызов Unload сам её не снимает.
55-C: для native-ресурса запишите пару acquire/release и владельца borrowed/owned. Для процесса задайте
framing, лимит длины, таймаут и порядок чтения двух потоков вывода. Отмена ожидания не завершает процесс.

DWORD остаётся 32-битным на Windows x64. SafeHandle выражает владение и lifetime, но неправильная
сигнатура всё ещё опасна. ALC помогает загрузке/выгрузке и не ограничивает права исполняемого кода.

## Глава 56

56-A: midpoint-to-even смотрит на ближайшую чётную последнюю цифру, поэтому 11.165 → 11.16.
Reference assemblies нужны компилятору; exe net48 требует Framework runtime.
56-B: сначала зафиксируйте смысл минимальной надбавки: применяется ли она к нулевой сумме, когда
округляется и что означает неправильная конфигурация. Только после этого извлекайте правило.
56-C: отделите изменения среды/формата от изменения поведения. Проверьте прежнего потребителя,
конфигурацию хоста и зависимости, которые невозможно заменить простым TargetFramework.

Конфигурация принадлежит executable-хосту. Binding redirect меняет разрешение версии сборки,
но не добавляет отсутствующий метод. Netstandard2.0 — совместимая поверхность API для выбранной пары runtime.

## Глава 57 и L07

57-A: сравнивайте не только размер exe, но и полный каталог, символы и необходимость внешнего runtime.
Для данного опыта результат размера файла одинаков; это не benchmark startup/throughput.
57-B: manifest должен перечислять весь набор файлов; иначе лишний конфиг может поменять поведение,
не затронув hashes известных DLL. Подпись/доверенный канал решают другую задачу, чем SHA-256.
57-C: сначала восстановите известный результат на опубликованном артефакте, затем переносите окружение.
Проверьте права, runtime/native dependencies, static files, внешнюю БД и key ring.

L07: в эталоне обе версии используют одну схему. Сначала проверьте readiness, потом отчёт food=1250
и повтор BatchId; после rollback и restore сумма не должна удвоиться. Версия 1.1.0 не доказывает
совместимость произвольной новой миграции. Backup в том же каталоге/на том же диске — только локальный опыт.

## Глава 58

58-A: live=200 подтверждает доступность процесса, ready=503 — неготовность выбранной зависимости/схемы.
В rate-опыте клиентский deadline ограничивает ожидание; report не должен зависеть от ненужного ему upstream.
58-B: завершите admission и writer, ожидайте worker до общего deadline. После его истечения явно
перечислите незавершённое; не печатайте Drained=true только потому, что StopAsync вернул управление.
58-C: до исправления соберите минимальное свидетельство, после — повторите тот же бизнес-запрос.
Для памяти найдите удерживающий root; для backup проверьте восстановление пользователя, суммы и receipt.

Вложенные retries расходуют общий бюджет. Graceful drain и crash recovery — разные гарантии.
Исправление инцидента должно иметь проверяемое действие и регрессию, а не только новый alert.

## Глава 59 и L08

59-A: 1250+500=1750, остаток 250; 1250+250+500=2000, остаток 0; 1250+751=2001,
отказ без записи. Invalid input отличается от корректного расчёта с Allowed=false.
Пустой набор новых строк важен для replay/дубликатов. Overflow проверяется до попытки commit.

59-B: owner берётся из auth, месяц из DateOnly. Сначала найдите прежний receipt, затем выделите
действительно новые строки и сгруппируйте их. Для всех групп используйте одну транзакцию.
Версия должна защищать объект, который меняет каждый конкурентный участник, а не случайную строку.
Один DbContext на поток не устраняет гонку двух независимых контекстов. Для SQLite исследуйте
busy/locking и ограниченный повтор всей операции; проверяйте инвариант после завершения обоих процессов.

59-C: подготовьте таблицу evidence заранее. Отдельная ссылка на зелёный CI без номера commit
не подтверждает сдаваемый код. В backup должны попадать бюджеты и receipt, а судьба внешних
эффектов после restore требует отдельного решения. Порог рубрики не отменяет блокирующий дефект.

Приёмка L08 оценивает ваш проект. BudgetPolicy — только арифметическая граница. Старый L06-код
после активации бюджетов нельзя считать безопасным rollback: он не применяет новое ограничение.

## Глава 60

Для карточек 1–5 проверьте: деление до преобразования; checked только в охваченном контексте;
копию value и общую ссылку; nullable как анализ; виртуальный dispatch; согласованность Equals/GetHashCode.
Для 6–10: variance относится к допустимым interface/delegate-позициям; closure/event держат ссылку;
IEnumerable не обещает снимок; IQueryable переводится провайдером; порядок patterns влияет на достижимость.
Для 11–15: IL/metadata не равны native image; Span — view с ограниченным lifetime; GC не гарантирует
своевременный Dispose; отмена кооперативна; atomic increment не объединяет несколько шагов проверки.
Для 16–20: сравнивайте измерения в одинаковых условиях; вносите контролируемый дефект; проверяйте
ограничения настоящего провайдера; связывайте auth с owner; восстанавливайте данные и выполняйте бизнес-запрос.

60-A: сначала письменно предскажите результат. Если после запуска гипотеза изменилась, сохраните оба
варианта и объясните причину. Недостаточно скопировать определение без контрпримера.
60-B: новый итог = прежний spent - старая сумма + новая сумма, с проверкой переполнения и version.
При отказе не изменяются ни expense version, ни агрегат, ни outbox. Повтор со старой version — конфликт,
не повторный delta. Даже уменьшение участвует в том же конкурентном протоколе.
60-C: выполните README буквально из нового checkout и запишите каждый отсутствующий шаг.
Если проверяли сами, укажите это. Не приписывайте независимое review автоматическому запуску скрипта.

В строгой границе первая ожидаемая регрессия — fixture exact. При двойном обходе — одноразовая
последовательность. «Любое исключение» не доказывает, что проверка обнаружила именно изучаемый дефект.
