# 52. Мобильные приложения и .NET MAUI

**Результат:** вы проектируете мобильный журнал, который сохраняет действие до появления сети,
повторяет пакет без удвоения расходов и не смешивает аккаунты. Нужны главы 31, 40–43, 46, 49–50.
Проверяемое ядро — [OfflineQueue](../../examples/Specializations/ClientCore/OfflineQueue.cs);
MAUI-оболочка собирается учащимся по шагам ниже на выбранной платформе.

## Что меняется на телефоне

Мобильная ОС вправе остановить процесс, пока пользователь смотрит другое приложение. Сеть может
смениться с Wi-Fi на мобильную, пропасть после успешного соединения или требовать входа в captive portal.
«Есть сеть» не означает «API принял запись». Операция сначала должна получить устойчивый локальный Id
и сохраниться; память страницы не является долговечным хранилищем.

MAUI объединяет .NET-логику и UI для Android, iOS, Windows и macOS через Mac Catalyst. Workload,
платформенный SDK, emulator/device и подпись — разные зависимости. Для Apple-сборок нужен соответствующий
Mac toolchain; наличие .NET SDK на Windows его не заменяет. Linux не является штатной desktop-целью MAUI.
Минимальные версии ОС и требования к Xcode/Android SDK проверяют для выбранной версии .NET и workload,
а не копируют из старого руководства.
[Поддерживаемые платформы](https://learn.microsoft.com/en-us/dotnet/maui/supported-platforms?view=net-maui-10.0),
[установка](https://learn.microsoft.com/en-us/dotnet/maui/get-started/installation?view=net-maui-10.0).

В этом выпуске мобильные workloads не установлены. Общая очередь исполняется и тестируется на .NET 10;
сборка Android/iOS, разрешения, lifecycle устройства и подпись **не выдаются за выполненные проверки**.
Ни основной verify.py, ни GitHub Actions не устанавливают мобильные SDK.

## MAUI UI, навигация и lifetime

ContentPage содержит визуальное дерево, BindingContext связывает его с view model. XAML похож на WPF,
но типы контролов, свойства и механизм платформенных handlers отличаются. Для списка используйте
CollectionView, для команды — Button.Command, для состояния — Label/ActivityIndicator. `x:DataType`
помогает компилятору проверять привязки. Генераторы CommunityToolkit должны соответствовать выбранному
target и требованиям AOT; не переносите неподдерживаемый шаблон без проверки предупреждений сборки.

Shell задаёт маршруты и навигацию. При передаче параметров храните устойчивый Id, затем загружайте
объект из хранилища: большой граф данных в query string создаёт проблемы с восстановлением и приватностью.
Страница может исчезнуть и вернуться; OnDisappearing не обязательно означает, что объект уничтожен.
Операция страницы и синхронизация приложения имеют разных владельцев CancellationTokenSource.
Не отменяйте общий сервис навсегда при каждом переходе между вкладками.
[Навигация Shell](https://learn.microsoft.com/en-us/dotnet/maui/fundamentals/shell/navigation?view=net-maui-10.0),
[жизненный цикл](https://learn.microsoft.com/en-us/dotnet/maui/fundamentals/app-lifecycle?view=net-maui-10.0).

```xml
<VerticalStackLayout Padding="24" Spacing="12">
    <Label Text="{Binding State}" />
    <Button Text="Обновить" Command="{Binding LoadCommand}" />
    <Button Text="Отмена" Command="{Binding LoadCancelCommand}" />
    <ActivityIndicator IsRunning="{Binding LoadCommand.IsRunning}" />
</VerticalStackLayout>
```

Это фрагмент содержимого ContentPage со стандартным MAUI XML namespace, не отдельный готовый XAML-файл.
В первом проходе назначьте BindingContext экземпляру ReportViewModel с DemoReportSource из ClientCore.
Затем подключите HTTP и долговечную очередь, не помещая SQL в обработчик нажатия.

## Договор локальной очереди

Каждый расход получает Guid при создании. Пакет получает свой BatchId один раз; его состав после записи
не меняется. Клиент сохраняет сериализованный снимок в SQLite-транзакции. Токен в SQLite не пишется.
Пример ограничивает пакет 100 строками/128 KiB, очередь — 100 пакетами на аккаунт. Достижение лимита
должно стать видимой ошибкой, а не молчаливым вытеснением старой покупки.
В Counts поле Pending считает все неподтверждённые пакеты, включая Blocked; Blocked — их подмножество.

```text
Локальная запись -> Pending -> HTTP с прежним BatchId
                              200 + корректная квитанция -> удалить из Pending
                              409 -> Blocked, требуется решение пользователя
                              timeout/нет сети/отмена -> оставить Pending
```

Локальный account key составляется из нормализованного адреса сервиса и устойчивого Id вошедшего
пользователя. Он разделяет очередь, но не доказывает личность: соответствие токена аккаунту обеспечивает
слой сессии. Вызов SyncAsync с другим ключом отклоняется до HTTP. При выходе сначала остановите и дождитесь
синхронизации, затем смените сессию и выберите другую очередь. Нельзя просто заменить поле Token посреди отправки.

В примере SQLite-команды синхронные и короткие. В настоящем UI дисковую работу выносите в сервис с
последовательным исполнителем; если используете Task.Run, не передавайте ему контролы и не считайте
отмену Task автоматическим прерыванием SQLite-транзакции. Не держите SQLite-транзакцию открытой через HTTP.

## Окно сбоя между двумя фиксациями

Сервер сохранил пакет, но приложение завершилось до локального DELETE. После запуска клиент снова видит
Pending. Он посылает **тот же BatchId и тот же payload**. L06 находит receipt и возвращает прежний результат.
Это повторяемая доставка с идемпотентным приёмом, а не магическое «ровно один раз» по нестабильной сети.
Если генерировать новый BatchId на каждой попытке, связь с серверной квитанцией исчезает.

```csharp
var queue = new OfflineQueue(path, accountKey);
queue.Enqueue(new ImportBatch(batchId, rows));
int sent = await queue.SyncAsync(
    accountKey, accessToken, transport, cancellationToken);
```

Enqueue отделяет снимок от изменяемого массива rows. Повтор BatchId с другим локальным payload отклоняется.
Успешный ответ проверяется: added + duplicates должен соответствовать количеству строк. Ответ 409 остаётся
Blocked и не уходит в бесконечный retry. Экран разрешения конфликтов пока не реализован: для исправленного
содержимого нужен новый пакет и явное решение судьбы старого. Правила сервера разобраны в [L06](../../labs/06-expense-api/README.md).

## Сеть, разрешения и секреты

Connectivity полезен как подсказка UI, но попытка HTTP и её результат остаются источником истины.
Retry запускайте с ограничением числа попыток и backoff; 401 требует обновления входа, 409 — разрешения
конфликта. Нельзя одинаково повторять все 4xx и проглатывать их до бесконечности.

AppDataDirectory подходит для приватных файлов приложения, Preferences — для небольших несекретных
настроек. Токены, которые действительно нужно сохранить, помещают в SecureStorage с обработкой ошибки
чтения/восстановления. SecureStorage не делает произвольную SQLite-базу зашифрованной и не отменяет
правила backup, выхода и удаления личных данных.
[Хранилище секретов](https://learn.microsoft.com/en-us/dotnet/maui/platform-integration/storage/secure-storage?view=net-maui-10.0).

Камера, геолокация и другие возможности требуют объявлений в манифесте и, где нужно, runtime-разрешения.
Запрашивайте их в контексте действия, объясняйте отказ и работайте без необязательной функции.
Сохранение в приватную папку приложения не означает, что нужно сразу просить доступ ко всем файлам.
Платформенную интеграцию оборачивайте интерфейсом: тесту журнала не нужен настоящий GPS.
[Разрешения](https://learn.microsoft.com/en-us/dotnet/maui/platform-integration/appmodel/permissions?view=net-maui-10.0).

## Пошаговая сборка мобильной оболочки

1. Выберите Android либо iOS и зафиксируйте SDK/workload, целевую ОС и реальное устройство или emulator.
   Проверьте `dotnet workload list`; установку выполняйте по официальной инструкции для своего хоста.
2. Создайте проект в work через `dotnet new maui -n MobileLedger -o work/MobileLedger`. Добавьте
   ProjectReference на ClientCore; target проекта должен быть совместим с net10.0.
3. Сначала покажите ReportViewModel с демонстрационным источником. Проверьте привязки, cancel и переход
   между страницами. Исправьте предупреждения XAML/AOT до подключения сети.
4. Зарегистрируйте долгоживущий сервис очереди с путём из FileSystem.AppDataDirectory. После входа выбирайте
   раздел аккаунта; при создании расхода сначала подтвердите локальный commit, затем показывайте Pending.
5. Подключите LedgerHttpClient к HTTPS API. `localhost` на телефоне — сам телефон; адрес хоста emulator
   и доверие сертификату задаются отдельно. Не отключайте проверку TLS ради работающего примера.
6. Добавьте кнопку Sync, счётчики Pending/Blocked, отмену, обработку 401 и сетевых ошибок. Из фонового
   callback обновляйте UI через MainThread/dispatcher. Не рассчитывайте на выполнение после остановки процесса.
7. Выполните матрицу ниже, затем соберите пакет нужной архитектуры, подпишите своим тестовым ключом и
   установите его. Ключи подписи и токены не добавляйте в Git.

## Проверяемый пример и матрица устройства

```text
dotnet run --project examples/Specializations/Scenarios -- offline .artifacts/mobile-demo.db
python tools/verify_specializations.py
```

CLI использует fake-сервер квитанций: Retained=1, Sent=1, Pending=0, Attempts=2, UniqueBatches=1.
Он намеренно падает в точке после удалённого приёма и переоткрывает реальный SQLite-файл. Тесты также
проверяют конфликт, сетевой отказ, отмену, неизменность снимка и разделение аккаунтов. Это проверка
алгоритма, а не фоновый сервис Android/iOS и не испытание потери питания.

На устройстве отдельно проверьте: авиарежим, выход из аккаунта с Pending, остановку процесса,
восстановление, запрет разрешения, истёкший токен, смену ориентации и обновление подписанного приложения
с сохранением очереди. Запишите исходный и конечный счётчики, чтобы «экран открылся» не подменил проверку данных.

## Контрольные вопросы и практика

1. Почему одинаковые BatchId и payload переживают потерю ответа безопаснее нового пакета?
2. Чем подсказка Connectivity отличается от подтверждения сервера?
3. Какую операцию нельзя считать выполненной только потому, что пользователь закрыл страницу?

**52-A.** Вход: один пакет и сбой после приёма. Выполните CLI и разберите четыре шага синхронизации.
Ожидается один уникальный пакет после двух попыток. Критерий: указана граница каждого commit и объяснено,
почему повторный запуск не требует восстановления данных из памяти.

**52-B.** Добавьте чтение списка Blocked и явное создание исправленного пакета. Вход: конфликт суммы
с сохранённым BatchId. Ожидаются неизменный старый снимок и новая операция с новым Id пакета после решения
пользователя. Критерий: тест не допускает потери Pending, бесконечного retry и смешения аккаунтов.

**52-C.** Соберите MAUI-оболочку на одной платформе по шагам выше. Вход: пять покупок offline,
остановка процесса, повторный вход и восстановление сети. Ожидается ровно пять расходов у правильного
владельца. Критерий: есть подписанный тестовый пакет, матрица устройства и инструкция воспроизведения;
проверка только ClientCore не засчитывается как запуск мобильного приложения.
