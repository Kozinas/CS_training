# Как проходить практикум C# и .NET

Этот курс учит писать, проверять и сопровождать программы на C#. Начинать можно без другого языка
программирования; достаточно уметь работать с файлами и терминалом. Первая цель — самостоятельно
сделать консольный отчёт по расходам. Затем программа развивается в библиотеку, импортёр, сервис
с базой данных и клиент выбранной специализации.

## Что уже можно изучать

Полностью подготовлен первый блок: главы 01–10, задания, подсказки, запускаемые примеры и лабораторная L01.
Продолжение подробно расписано в [программе](../PLAN.md); будущие главы отмечены как план.
Это позволяет проходить материал последовательно и видеть, какие знания ещё предстоит получить.

## Один учебный цикл

1. Прочитайте цель главы и попробуйте ответить на контрольные вопросы.
2. Перепечатайте небольшой пример и до запуска предскажите результат.
3. Измените одно условие: пустой ввод, границу диапазона, тип или порядок действий.
4. Решите A и B самостоятельно. В C переносите приём на изменившееся требование.
5. Запишите вход, ожидаемый и фактический результат. Объясните расхождение, если оно есть.
6. Сверьтесь с [подсказками](appendices/hints.md) и повторите задачу без готового решения.

Удобный ритм занятия — 15–25 минут чтения, 40–60 минут кода, 10 минут разбора.
Это ориентир для одного подхода, а не обещание освоить главу за час.
Если не удаётся объяснить строку программы, уменьшите пример до нескольких инструкций.

## Уровни практики

| Уровень | Что требуется | Когда задача решена |
| --- | --- | --- |
| A | Применить один приём по образцу | Результат совпал, каждая строка объяснима |
| B | Самому выбрать и связать несколько приёмов | Пройдены обычные и граничные случаи |
| C | Изменить требования или диагностировать дефект | Старое поведение сохранено, новое проверено |
| L | Собрать законченный этап проекта | Выполнен весь контракт, другой человек может запустить программу |

Для B и C проверяйте хотя бы обычный случай, нижнюю и верхнюю границы, ошибочный ввод.
Для коллекций добавляйте пустой набор и дубликат; для файлов — отсутствие и повреждение;
для async в последующих блоках — отмену и частичный сбой.

## Рабочие файлы

Главы находятся в `docs`, законченные примеры — в `examples`, условия лабораторных — в `labs`.
Свои решения создавайте в `work/имя-задачи`; эта папка не включается в Git.
Исходный `ConsoleApp1` — отдельный учебный проект пользователя. Примеры курса собираются своей solution.

Команды в тексте выполняются из корня репозитория, если явно не сказано иначе.
В Windows подходят PowerShell и терминал IDE. Пути в командах используют `/`, который понимает .NET.
Перед изменением примера полезно сделать копию в `work`.

## Быстрый маршрут при опыте другого языка

Прочитайте 01, выполните B и C из 03, 05–09 и сдайте L01. Если все критерии выполнены,
можно переходить к системе типов. Особое внимание уделите `decimal`, nullable-аннотациям,
копированию ссылок, `IDisposable` и культурно зависимому разбору строк: привычки другого языка
здесь часто приводят к ошибкам.

## Как пользоваться книгами

Книги из `Books` — дополнительное углубление. Для первых глав они не обязательны.
Книга Рихтера полезна при изучении CLR, типов и ресурсов. Книги Freeman и Yan нужны для веб-раздела.
Версии ASP.NET Core 6/8 в этих изданиях отличаются от платформы курса, поэтому команды и API
сверяются с актуальной документацией. Названия файлов и назначение приведены в
[списке источников](appendices/sources.md).

## Проверка первого результата

После главы 10 вы должны без образца разобрать строку расхода, выбрать тип суммы, объяснить
поведение общей ссылки на список, закрыть файл при ошибке и вернуть понятный код завершения.
Если какой-то пункт вызывает затруднение, вернитесь к соответствующей главе.
Готовность определяется этими действиями, а не количеством прочитанных страниц.
